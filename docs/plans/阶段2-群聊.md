## 需要你手动做的事

编号 `U01…` 只在本计划里用，代码和注释不引用。

### U01　每期完成后部署

- **在哪**：Kioku 所在的 Docker 主机。
- **操作**：先按 README 备份，再拉取代码、重新构建镜像并启动；迁移在启动时自动执行。
- **验证**：`/v1/health` 的 version 与部署的提交一致，管理界面能打开。
- **回滚**：按 README「回滚」恢复备份。
- **告诉 agent**：「第 N 期部署好了」，或让 agent 部署。

### U02　配抽取模型（第 2 期部署之后）

- **在哪**：new-api 管理界面，以及 Kioku 的「实例设置」。
- **操作**：在 new-api 给 Kioku 建一个令牌（只给要用的模型），在 Kioku「实例设置 → 抽取模型」填接口地址、模型与令牌。
- **验证**：设置页的连通性测试通过。
- **回滚**：清空抽取模型的设置，抽取随即停止。
- **告诉 agent**：「抽取模型配好了」。

### U03　合并加了 Python 检查的门禁改动

- **在哪**：GitHub 上 agent 开的 PR（`scripts/pr.sh --no-merge`）。
- **操作**：审阅 `scripts/check.sh` 与 CI 里新增的 Python 检查（SDK 与插件的测试、格式），没问题就合并。门禁改动按 AGENTS.md 只能由你合并。
- **验证**：合并后的 CI 跑过 Python 检查。
- **回滚**：revert 这个 PR。
- **告诉 agent**：「门禁合了」。

### U04　把插件装到 AstrBot（第 3 期之后）

- **在哪**：AstrBot 所在的主机。
- **操作**：插件目录放进 AstrBot 的插件目录并重启，或在 AstrBot 管理界面安装；填 Kioku 地址与一把群聊 bot 用的 Key。也可以让 agent 来装（算部署，要你同意）。
- **验证**：AstrBot 网页聊天里能看到注入的召回，Kioku 的召回分析里出现这个应用的调用。
- **回滚**：在 AstrBot 里停用插件。
- **告诉 agent**：「插件装好了」。

## 分阶段任务

### 1 · 会话上下文与对象

- [x] 契约：生命周期事件（`session.start`、`prompt.submit`，以及第 2 期的 `turn.end`）与 REST 召回可以带 `context`：`chatType`（direct / group / channel / cron / subagent）、`platform`、`group`、`sender`（平台账号与显示名）；格式不对返回 400，不带时照旧按无上下文。显示名为空当作没带，只记前 128 个字，不因为名字长拒掉整轮召回
- [x] 对象解析：按（平台、种类、平台账号）找对象，找不到就建（人或群），显示名随上报更新（人的名字只按私聊里报的更新，群里报的可能是群名片，只在还没记下名字时用；主人改过名字后只更新平台显示名；注入对话时用平台上的名字）；同一个请求里的群与发言人各解析一次。平台账号表加了种类（QQ 的群号与 QQ 号是两套编号）与平台显示名，外键带上种类，人和群合并不到一起；同一个新账号的并发请求按账号的咨询锁排队，只建出一个对象
- [x] 会话上下文：解析出的对象交给 `resolveAccess`；对象关联了应用主人的账号时算主人私聊（决策 4）；写入的来源作用域与来源按上下文（`memoryServiceForKey` 接收会话，带上下文的写入入口在第 2 期的 `turn.end`）
- [x] 按群换人格：新表 `app_group_personas`（带外键，进 RLS），接口 `GET / PUT /v1/spaces/{spaceId}/apps/{appId}/group-personas`，只有应用主人能改、只能按群配；没有规则的用默认人格；boot、召回与写入都按规则选出的人格；人格被规则用着时不能删
- [x] 召回加对象直连：当前发言人与本群的对象层里抽取的事实，先套读权限，不看查询直接注入：REST 召回返回 `subjects`，`prompt.submit` 在召回块后附 `<kioku-subjects>` 块（设计 7 节）

### 2 · 对话缓冲与抽取

- [x] `turn.end`：本轮用户消息与回复追加进会话缓冲（新表 `conversation_turns`，进 RLS），按应用与来源作用域分批（不按插件给的会话标识，免得私聊混进群里的那一批）；攒满 10 轮或空闲 10 分钟排一次抽取任务（pg-boss 的 `upsert` 按批推后开始时间，`stately` 队列保证每批同时只有一个）；没配抽取模型时不缓冲，缓冲后设置被清掉的到点丢弃；Key 写不了对象层与情节层时不缓冲、不建对象；每批最多留 100 轮；整批空闲超过一天的由清理任务删掉（决策 5）
- [x] 抽取模型的设置：实例设置里配接口、模型与 Key（Key 加密存库，和嵌入接口共用一套存储与换主机的规则），带连通性测试，可以清除；实例设置页的卡片提前到这一期做（U02 在这一期部署后就要填）
- [x] 抽取任务：让模型按 JSON 输出候选事实，与相关对象已有的记忆比对，决定 ADD / UPDATE（旧条目设 `valid_to`）/ NONE；写进对象层（挂对象）与情节层（会话摘要，30 天到期），来源与来源作用域按会话上下文；像明文凭据或带凭据占位符的事实丢掉，摘要里的打码。权限按写入那一轮的 Key 重新算，吊销、作废、写不了时不请求模型
- [x] 抽取记录：新表 `extraction_runs`（进 RLS），每抽取一批记下涉及的对象、轮数、用量、各项条数与失败原因，给对象页看；抽取完删掉用过的缓冲，抽取期间新进来的留着（空闲超过一天的清理已随缓冲做了）
- [ ] 预算：每个对象每天的写入条数上限，每个空间的月度 token 预算（决策 6），用到 80% 时在概览提醒，超出后只写会话摘要，下个周期恢复
- [ ] 验证：集成测试覆盖攒批与空闲触发、ADD / UPDATE / NONE、来源作用域、超预算降级、条数上限、没配模型时丢弃；模型用假的实现，不连外部接口

### 3 · Python SDK 与 AstrBot 插件

- [ ] `sdks/python`：由服务端的 OpenAPI 生成客户端（生成工具与版本写死），覆盖生命周期、召回与记忆接口；带最小的测试
- [ ] 门禁：把 Python 的格式检查与测试加进 `scripts/check.sh` 与 CI。门禁改动，单独开 PR（`--no-merge`），维护者合并（U03）
- [ ] `plugins/astrbot`：`on_llm_request` 时取平台、群与发言人，调 `prompt.submit` 把召回块注入系统提示；回复发出后调 `turn.end`；Kioku 不可用时静默降级，不打断对话
- [ ] 插件配置：Kioku 地址与 Key；平台账号原样上报，由服务端解析成对象
- [ ] 验证：用构造的 AstrBot 事件测私聊、群聊、主人私聊三种情形，确认上报的上下文与注入的内容；对开发库跑一遍

### 4 · 管理界面

- [ ] 对象页：人与群的列表、各自的平台账号、手动合并（只合并身份，记忆的来源作用域不变）、标记为主人；每个对象的记忆与抽取记录
- [ ] 待审队列：不可信来源写入的对象层与情节层内容，主人可以确认（改成受信）或删除
- [ ] 设置：空间设置里的预算与当月用量；应用配置里的会话规则（按群换人格）。实例设置里的抽取模型已在第 2 期做了
- [ ] 验证：无头 Chrome 走查（CSP 下没有 eval、没有外部请求，窄屏）

### 5 · 验证

- [ ] 模拟的群聊端到端：插件处理构造的群聊事件，连部署了本阶段的 Kioku，验证借用人格、按群友记忆、读不到私人层与画像层、群里写不进受信的层
- [ ] 阶段 2 的结束标志确认后，更新设计 12 节的状态

## 待办（审查中发现、留到后续 PR 的问题）

- 第 4 期合并对象时，按群换人格的规则要跟着移到保留的对象上：现在删掉对象会连带删掉规则（外键 cascade）
- 第 4 期：召回调试台与启动预览能模拟会话上下文（选群与发言人），现在只能按无上下文模拟
- 第 3 期：确认 AstrBot 能不能调 MCP 工具；不能的话，只有 URI 与线索的召回块对群聊 bot 用处有限，要考虑按运行时家族直接带正文
- 以后：抽取的事实也进前几路召回（问到别的群友时能想起来）；现在只有对象直连带出当前发言人与本群的事实
- 第 4 期：只读的 Key 带上下文时也会建对象，数量不设上限，泄露的 Key 能灌进大量对象。考虑只有能写对象层的 Key 才建，或给每个空间的对象数设上限，对象页要能批量清理
- 按群换人格的规则只在接口里检查对象是群，数据库没有约束；现在没有改对象种类的路径，合并对象时（第 4 期）要保证只合并同种类的
- 嵌入接口与抽取模型的设置卡片是两份相似的表单，两个客户端的请求代码也相似；再加 OpenAI 兼容的接口时抽成共用的组件与请求函数
