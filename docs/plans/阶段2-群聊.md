| 4 | 主人靠对象认：对象关联了应用主人的账号（管理界面里「标记为主人」）时，这个人的私聊算主人私聊 | 设计 4.2 节「主人私聊」：靠平台账号认出主人；关联放在对象上，同一个人合并过的多个平台账号都算 | 有了 `/bind` 自助绑定（阶段 3）之后改为绑定 |
| 5 | 对话缓冲只是抽取的输入：抽取完就删，空闲超过一天的也删；不进召回、不进活动 | 群聊原文里有别人的话，不该长期留；要留的是抽取出的事实与摘要 | — |
| 6 | 预算默认值：每个空间每月 200 万 token，每个对象每天最多写 20 条；空间设置里可调 | 设计 6.4 节要两道成本控制；默认值按一个活跃群一个月的量估，宁可先紧 | 实际用量出来之后调 |
| 8 | 合并对象时，被合并对象的私聊（群）里记下的内容来源作用域换成保留的对象，仍只在和这个人的私聊（这个群）里可见 | 维护者（2026-10-29）；原样保留的话合并后私聊再也读不到 | — |
| 9 | 确认过的事实遇到群里的新说法：新说法当作新的待审事实，确认过的不被推翻；对象页上能删事实，留哪条由成员决定 | 维护者（2026-10-29） | 两条并存的情况多了，再做「确认新的时一并推翻旧的」 |
| 7 | 群聊 bot 不调记忆工具：运行时家族 `astrbot` 的召回块直接带正文的开头，会话开始不附只有 URI 的内容；插件说明里写明不要给它接 Kioku 的 MCP | 不带会话上下文的请求（MCP）按 Key 的全部权限读写，群里能借它读到私人层；群聊每轮一次调用就要回复，调工具多一轮往返、模型也不一定会调 | 生命周期以外的接口也能带会话上下文时，再考虑给群聊 bot 工具 |

- **验证**：设置页的连通性测试通过。
- **回滚**：清空抽取模型的设置，抽取随即停止。

### U04　把插件装到 AstrBot（第 3 期之后）

- **在哪**：AstrBot 所在的主机。
- **操作**：按插件的 README 把 `plugins/astrbot_plugin_kioku` 复制进 AstrBot 的插件目录（`cp -RL`，跟随客户端的符号链接）并重载插件；在 Kioku 建一个运行时家族为 astrbot 的应用、签发 README 里说的那种 Key，填进插件配置。不要再给这个 bot 接 Kioku 的 MCP（决策 7）。也可以让 agent 来装（算部署，要你同意）。

- **回滚**：在 AstrBot 里停用插件。
- **告诉 agent**：「插件装好了」。

## 分阶段任务

### 1 · 会话上下文与对象

- [x] 契约：生命周期事件（`session.start`、`prompt.submit`，以及第 2 期的 `turn.end`）与 REST 召回可以带 `context`：`chatType`（direct / group / channel / cron / subagent）、`platform`、`group`、`sender`（平台账号与显示名）；格式不对返回 400，不带时照旧按无上下文。显示名为空当作没带，只记前 128 个字，不因为名字长拒掉整轮召回
- [x] 对象解析：按（平台、种类、平台账号）找对象，找不到就建（人或群），显示名随上报更新（人的名字只按私聊里报的更新，群里报的可能是群名片，只在还没记下名字时用；主人改过名字后只更新平台显示名；注入对话时用平台上的名字）；同一个请求里的群与发言人各解析一次。平台账号表加了种类（QQ 的群号与 QQ 号是两套编号）与平台显示名，外键带上种类，人和群合并不到一起；同一个新账号的并发请求按账号的咨询锁排队，只建出一个对象
- [x] 会话上下文：解析出的对象交给 `resolveAccess`；对象关联了应用主人的账号时算主人私聊（决策 4）；写入的来源作用域与来源按上下文（`memoryServiceForKey` 接收会话，带上下文的写入入口在第 2 期的 `turn.end`）
- [x] 按群换人格：新表 `app_group_personas`（带外键，进 RLS），接口 `GET / PUT /v1/spaces/{spaceId}/apps/{appId}/group-personas`，只有应用主人能改、只能按群配；没有规则的用默认人格；boot、召回与写入都按规则选出的人格；人格被规则用着时不能删
- [x] 召回加对象直连：当前发言人与本群的对象层里抽取的事实，先套读权限，不看查询直接注入：REST 召回返回 `subjects`，`prompt.submit` 在召回块后附 `<kioku-subjects>` 块（设计 7 节）

### 2 · 对话缓冲与抽取

- [x] `turn.end`：本轮用户消息与回复追加进会话缓冲（新表 `conversation_turns`，进 RLS），按应用与来源作用域分批（不按插件给的会话标识，免得私聊混进群里的那一批）；攒满 10 轮或空闲 10 分钟排一次抽取任务（pg-boss 的 `upsert` 按批推后开始时间，`stately` 队列保证每批同时只有一个）；没配抽取模型时不缓冲，缓冲后设置被清掉的到点丢弃；Key 写不了对象层与情节层时不缓冲、不建对象；每批最多留 100 轮；整批空闲超过一天的由清理任务删掉（决策 5）
- [x] 抽取模型的设置：实例设置里配接口、模型与 Key（Key 加密存库，和嵌入接口共用一套存储与换主机的规则），带连通性测试，可以清除；实例设置页的卡片提前到这一期做（U02 在这一期部署后就要填）
- [x] 抽取任务：让模型按 JSON 输出候选事实，与相关对象已有的记忆比对，决定 ADD / UPDATE（旧条目设 `valid_to`）/ NONE；写进对象层（挂对象）与情节层（会话摘要，30 天到期），来源与来源作用域按会话上下文；像明文凭据或带凭据占位符的事实丢掉，摘要里的打码。权限按写入那一轮的 Key 重新算，吊销、作废、写不了时不请求模型
- [x] 抽取记录：新表 `extraction_runs`（进 RLS），每抽取一批记下涉及的对象、轮数、用量、各项条数与失败原因，给对象页看；抽取完删掉用过的缓冲，抽取期间新进来的留着（空闲超过一天的清理已随缓冲做了）
- [x] 预算：每个对象每天的写入条数上限，每个空间的月度 token 预算（决策 6，按 UTC 的自然月、自然日），用到 80% 时在概览提醒，超出后只写会话摘要，下个周期恢复。空间设置里的预算卡片（看用量、owner 改上限）提前到这一期做
- [x] 验证：集成测试覆盖攒批与空闲触发、ADD / UPDATE / NONE、来源作用域、超预算降级、条数上限、没配模型时丢弃；模型用假的实现，不连外部接口（`buffer.int.test.ts`、`extract.int.test.ts`、`budget.int.test.ts`）

### 3 · Python SDK 与 AstrBot 插件

- [x] `sdks/python`：由服务端的 OpenAPI 生成客户端（openapi-python-client 0.29.1，`generate.sh`），只收接入方用的接口（Key 鉴权的生命周期、召回、boot、记忆与 whoami）；契约里给这些接口用到的对象 schema 起了名（`.meta({ id })`），生成的模型名才可读；枚举不起名，免得 MCP 工具的输入 schema 变成 `$ref`；带最小的测试（MockTransport）。要 Python 3.11 以上（生成的代码用了 `StrEnum` 与 `typing.Self`）；运行时依赖只给范围（会装进宿主的环境），开发工具写死，生成工具的间接依赖用 `--exclude-newer` 按日期锁住；SDK 与接口是否同步的检查放进门禁的 PR
- [ ] 门禁：把 Python 的格式检查与测试加进 `scripts/check.sh` 与 CI。门禁改动，单独开 PR（`--no-merge`），维护者合并（U03）
- [x] `plugins/astrbot_plugin_kioku`（AstrBot 按目录名认插件，名字照它的约定）：`on_llm_request` 时取平台、群与发言人，同时调 `session.start` 与 `prompt.submit`；启动上下文追加到系统提示（按会话缓存 10 分钟，不破坏服务商的提示缓存），召回块作为临时的额外用户内容（不进对话历史）；`on_llm_response` 后不等待地调 `turn.end`；Kioku 不可用、超时、拒绝时只记日志，不打断对话。服务端给 `astrbot` 家族的召回块直接带正文的开头、会话开始不附只有 URI 的内容（决策 7）。客户端是指向 `sdks/python/kioku_client` 的符号链接，安装时复制要跟随链接
- [x] 插件配置：Kioku 地址、Key、是否注入启动上下文、超时；平台账号原样上报，由服务端解析成对象
- [x] 验证：用构造的 AstrBot 事件测私聊、群聊、主人私聊三种情形，确认上报的上下文与注入的内容；对开发库跑一遍

### 4 · 管理界面

- [x] 对象页：人与群的列表（按种类筛选、按名字或平台账号查找、游标翻页）、各自的平台账号与事实条数；详情里有记下的事实（带来源：哪个群、和谁的私聊）、群或私聊的会话摘要、涉及它的最近 20 批抽取；改名（之后平台上的显示名再变也不跟）；「这是我」：成员只能把人标记成自己，已是别人的返回 409，只能取消自己的，空间 owner 能取消任何人的；owner 与 editor 能改，viewer 只能看
- [x] 合并对象（决策 8）：对象详情里选同种类的另一个对象合并进来，平台账号、挂在它身上的事实、对话缓冲与抽取记录都归到保留的对象；它的私聊（群）作用域换成保留对象的；按群换人格的规则跟过来，两边在同一个应用都有规则时留保留的；只有被合并的那个标记了成员时标记跟过来，两边标记了不同成员时 409；名字与改名锁留保留对象的；移过来的缓冲按合并后的批次再排一次抽取。对象页上每条事实能删（决策 9，带版本）
- [x] 待审队列：不可信来源写进对象层与情节层、现在有效、读得到的内容，按层筛选、新的在前；owner 与 editor 勾选后确认（来源改成主人，记 confirm 事件）或删除（确认框里写明抽取的内容删掉后管理界面里不能恢复）；带着列表里看到的版本处理，别人处理过的、看过之后被改过的跳过并告知条数；viewer 只能看。顺带补上：不可信来源只能改动不可信来源写下的记录（`canModify`），确认过的事实不会被群里的抽取推翻
- [x] 设置：应用详情里的「按群换人格」：列出规则（群名链到对象页）、改人格、删规则，选群时按群名或群号到服务端查、已有规则的群不再列出；只有应用主人能改，其他成员只能看。规则接口返回时带上群现在的名字。实例设置里的抽取模型、空间设置里的预算与当月用量已在第 2 期做了
- [x] 验证：无头 Chrome 走查（CSP 下没有 eval、没有外部请求，窄屏）：对象、合并、删事实、待审、按群换人格、抽取模型与预算的设置都走了一遍，宽屏与 390 宽都正常（见验证记录）

## 待办（审查中发现、留到后续 PR 的问题）

- 以后：召回调试台与启动预览能模拟会话上下文（选群与发言人），现在只能按无上下文模拟
- 以后：抽取的事实也进前几路召回（问到别的群友时能想起来）；现在只有对象直连带出当前发言人与本群的事实
- 以后：只读的 Key 带上下文时也会建对象，数量不设上限，泄露的 Key 能灌进大量对象。考虑只有能写对象层的 Key 才建，或给每个空间的对象数设上限，对象页要能批量清理
- 嵌入接口与抽取模型的设置卡片是两份相似的表单，两个客户端的请求代码也相似；再加 OpenAI 兼容的接口时抽成共用的组件与请求函数
- 合并对象不改历史快照里的来源作用域：Key 按会话上下文看合并过来的记忆的历史时，合并前的那几版看不到；要看就得在合并时一并改写快照，或者看历史时把合并记录考虑进去
- 按群换人格的规则整组替换：两个标签页同时改时，后保存的会覆盖前一个的改动且不提示。要么改成逐条的接口，要么整组保存时带上版本
- 确认过的事实遇到群里的新说法时两条并存（决策 9 先做了对象页上删事实）；以后可以让待审项标出它想推翻哪一条、确认时一并推翻，抽取的提示语里也可以标出哪些事实不能推翻
