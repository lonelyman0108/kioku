## 分阶段任务

### 1 · 服务端健壮性

- [ ] 请求体格式错误（不是合法 JSON 等）返回 400 而不是 500：`app.ts` 的 `onError` 按 hono 的 `HTTPException` 自己的状态码返回
- [ ] 待审队列的 `review()` 等只改非键列的地方改用 `FOR NO KEY UPDATE SKIP LOCKED`：外键插入加的 KEY SHARE 不再让记忆被当成锁住而跳过
- [ ] 合并对象时删掉被移动记忆的 Dream 整理标记，合并带来的重复会被重新整理
- [ ] Dream 给私人段固定留几次请求：共享内容积压时私人范围照样能整理，留量与有没有私人内容无关

### 2 · 管理界面体验

- [ ] 已删除列表说明「删除超过 N 天会被永久清除」，每条显示大约还剩几天（暂停期间按暂停结束时间算）；接口带上保留天数
- [ ] 换嵌入模型时新渠道换了主机、Key 留空：提交前就在那个渠道旁提示，不再等服务端报「填 null」
- [ ] 自动识别的网址遇到全角标点与中日韩文字就结束，不把后面的中文链进去
- [ ] 概览与实例设置的向量数用同一个口径

### 3 · 数据与性能

- [ ] 写入后生成向量的任务一次取一批（或缩短轮询），一条失败只影响这一条、照旧重试
- [ ] 按空间导出带上已过期与被推翻的记忆（决策 1）
- [ ] 导出的发送设时限，客户端一直不读响应时到点放掉名额

## 以后再做（不在这一轮）

- 召回排序的时间衰减（设计 4.4 节）
- 凭据的取用记录和别的凭据事件一样按保留期删（默认 30 天之前的取用就查不到了）；要不要单独更长的期限，等维护者定
- 推翻它的事实被删掉之后，被推翻的那条不会自动恢复，由成员在对象页的「被推翻的事实」里处理（维持现状）
- Dream 的月度预算用量所有成员都看得到，能推断出有人的私人内容被整理；要完全挡住得按成员分预算
- 做成员管理时（管理界面与凭据计划第 4 期）：Dream 私人内容开关存在成员那一行上，成员被移出再加回会回到默认开；移除成员的事务与 Dream 写结果时锁成员行的顺序要一致，免得死锁
