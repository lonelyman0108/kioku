## 分阶段任务

### 1 · 服务端健壮性

- [x] 请求体格式错误（不是合法 JSON 等）返回 400 而不是 500：`app.ts` 的 `onError` 按 hono 的 `HTTPException` 自己的状态码返回（格式错 400、太大 413、类型不对 415，回复 `{ error }`，不打堆栈）
- [x] 待审队列的 `review()` 等只改非键列的地方改用 `FOR NO KEY UPDATE SKIP LOCKED`：外键插入加的 KEY SHARE 不再让记忆被当成锁住而跳过
- [x] 合并对象时删掉合并后要放在一起看的记忆的 Dream 整理标记（两边私聊或群作用域里的，以及被合并对象有记忆的作用域里关于这两个对象的），合并带来的重复会被重新整理
- [x] Dream 给私人段固定留 2 次请求、1.5 万 token：共享内容积压时私人范围照样能整理，留量与有没有私人内容无关

### 2 · 管理界面体验

- [x] 已删除列表说明「删除超过 N 天会被永久清除」，每条显示大约还剩几天（暂停期间按暂停结束时间算）；接口带上保留天数
- [x] 换嵌入模型时新渠道换了主机、Key 留空：提交前就在那个渠道旁提示（抽取模型与备份设置也一样），不再等服务端报「填 null」
- [x] 自动识别的网址遇到全角标点与中日韩文字就结束，不把后面的中文链进去
- [x] 概览与实例设置的向量数用同一个口径（只算现在有效、不是 secret、有正文的策展记忆；过期记忆的向量由每小时的清理删掉，重新生效时再生成）

### 3 · 数据与性能

- [x] 写入后生成向量的任务一次取一批（或缩短轮询），一条失败只影响这一条、照旧重试
- [x] 按空间导出带上已过期与被推翻的记忆（决策 1）
- [x] 导出的发送设时限，客户端一直不读响应时到点放掉名额（2 分钟没有进度或 30 分钟没发完就断开；文件分块交给响应流，真的发出去才算发完）

## 以后再做（不在这一轮）

- 召回排序的时间衰减（设计 4.4 节）
- 向量的错误判断里批处理之前就有的几处：一批里最短的 3 条都是超长文本时补齐会停下（下一遍又停在同一处）；接口在一批中途挂掉时剩下的每条都单独请求一次；单条写入时 Key 错了记成「这条拿不到向量」而不是接口不可用。要彻底改得按一次运行记住接口是否可用
- 凭据页的已删除列表、已过期里标「已让出」的记录同样会按保留期被永久删除，还没有倒计时
- 合并对象在 Dream 请求模型期间整个做完、提交时，保留对象那边没变的记忆仍会被标成看过（被移过来的那些照样会被看）；要完全挡住得给每个范围加「合并版本号」之类的东西，要加迁移。合并事务开着时与 Dream 写标记交错的情况已经挡住（合并先锁住要一起看的记忆）
- `embedding/worker.ts` 对记忆用 `FOR UPDATE SKIP LOCKED` 但不改它，`crypto/rotation.ts` 改的也不是键列：同样会把外键插入的锁当成正在改，都会稍后重试，影响小
- 未知的 `/v1` 路径返回纯文本的「404 Not Found」，不是 `{ error }` 的格式
- 凭据的取用记录和别的凭据事件一样按保留期删（默认 30 天之前的取用就查不到了）；要不要单独更长的期限，等维护者定
- 推翻它的事实被删掉之后，被推翻的那条不会自动恢复，由成员在对象页的「被推翻的事实」里处理（维持现状）
- Dream 的月度预算用量所有成员都看得到，能推断出有人的私人内容被整理；要完全挡住得按成员分预算
- 做成员管理时（管理界面与凭据计划第 4 期）：Dream 私人内容开关存在成员那一行上，成员被移出再加回会回到默认开；移除成员的事务与 Dream 写结果时锁成员行的顺序要一致，免得死锁
