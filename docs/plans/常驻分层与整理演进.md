# 常驻分层加载、跨记忆整理与模型思考配置演进计划（Kioku）

> 状态：进行中　　开始：2026-11-27　　负责人：维护者 / agent
> 全部完成后，文件头改为「已完成 YYYY-MM-DD」，用 `git mv` 移到 `docs/archive/plans/`。

面向 Kioku 单人自托管 12 张扁平表架构（[ADR-0004](../adr/0004-flat-single-owner-v2.md)），承接 [记忆结构与历史分离.md](./记忆结构与历史分离.md)，结合生产使用痛点、主流竞品（Claude Code / Cursor / Letta / Mem0 / Zep / A-MEM）及 Anthropic《[The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)》的四层记忆与离线整理方法论，按 **3 期独立 PR** 系统解决以下问题：

1. **模型推理控制与后台调用韧性不足**：对话模型配置缺少思考等级（`reasoning_effort`）控制，无法为快速前台任务与深度后台整理差异化分配推理算力；同时整理链路在 HTTP 层、业务解析层与 `pg-boss` 队列层均缺乏重试与容错（含流式僵死/提前截断检测、`<think>` 块清洗及坏 JSON 静默吞错推进水位漏洞）。
2. **顶层启动加载（Boot）膨胀与跨场景串场**：二元 `is_pinned` 迫使长篇参考手册与极简行为铁律共享同一全文槽位，既挤爆预算又降低模型遵循率；未列入固定枚举的客户端（如 `zcode`）在导入与界面均无法打标导致全局串场；部分客户端缺少宿主字数帽、超预算排序存在「字数优先于场景精准度」反转、`loadRecentEntries` 未做场景冲突过滤，且列表页常驻字数统计跨场景裸加总造成误判。
3. **整理链路偏重单条格式、跨记忆能力薄弱且缺少主动单条入口**：现有 `tidy` 仅逐条清洗，常规后台整理未利用已有 1024 维 `entry_embeddings` 向量、`findFtsNeighbors` 未按相关性排序、1,500 字截断直接封杀长文 `merge_duplicates` 提案、缺少「补全双链」与「常驻层降级/防漂移」建议，合并删除重复项后也未重定向其他词条的入链；同时缺少针对单条或选中词条主动触发规范整理与查重关联的入口。

**架构红线**：严格保持 **12 张扁平表、无 RLS、自由 Markdown**（不引入独立图数据库、不拆三元组实体库、不新增顶级导航）；所有表结构改动为 `0001_entry_structure_and_history` 之后的纯增量迁移（不改已有迁移文件）；保持与 `kioku-plugins`（`/v1/lifecycle/event`、`/v1/boot`、`/v1/recall`、`/v1/whoami`、`/v1/credentials/resolve`）及 `access/scope.ts` JS/SQL 双重权限边界 100% 向后兼容；坚守「待处理收件箱人工审阅 + 乐观锁 + 版本历史」护城河，绝不静默直改主库；界面严守纸墨风（Paper & Ink）、零圆角/零阴影、1px 墨线与 `copyRules.test.ts` 用语规范。

## 决策摘要

| # | 决策 | 采纳 | 可推翻条件 |
|---|---|---|---|
| 1 | 模型思考等级选项与默认行为 | 在 `chat_llm` 配置新增 `reasoningEffort: 'default' \| 'off' \| 'low' \| 'medium' \| 'high'`（界面中文：`跟随默认 / 关闭 / 低 / 中 / 高`）；**`default` 绝对不向请求体注入思考字段**，100% 兼容非推理模型与网关模型名后缀；无 DDL 迁移（写入 `settings` JSONB） | 未来需要独立管理多套上游模型路由池而非单 `chat_llm` 端点 |
| 2 | 思考等级粒度与协议兼容 | 全局默认思考等级 + 可折叠的「按任务覆盖」两档：**快速任务**（随手记归并 + 会话摘要）与**整理任务**（后台整理 + 规范整理）。统一发送 OpenAI 兼容顶层 `reasoning_effort`（`off` 映射 `'none'`），开启思考时自动按档位补偿 `max_tokens`（含测试连接提升至 `≥256`）并处理 `temperature` 冲突；测试连接当场探测、运行时遇不支持 400 自动剥离重试并按 `(baseUrl, model, effort)` 进程内缓存 1h | 上游协议生态彻底分裂且无法经 OpenAI 兼容网关统一转发 |
| 3 | 错误重试分层边界 | 传输层按结构化 `ModelClientError` 区分可重试（`408/429/5xx/520–524`、断连、SSE 45s 空闲超时、未见 `[DONE]` 截断）与立即失败（`401/402/403/404/413/400/insufficient_quota/context_length_exceeded/finish_reason==='length'`）；指数退避 + Full Jitter + 尊重 `Retry-After`；语义/完整性纠错最多 1 次（先剥离 `<think>...</think>`）。严格控制 HTTP × `pg-boss` 不相乘：整理任务 HTTP `2` 次 + `pg-boss` `0` 次；摘要抽取 HTTP `1` 次 + `pg-boss` `3` 次；向量任务 HTTP `1` 次 + 沿用 `pg-boss` 既有配置；热路径 `recall` 保持 `0` 次立即降级 BM25 | 改为引入分布式任务协调与独立外部限流队列 |
| 4 | 常驻加载三态模型（`boot_mode`） | 不硬禁写入，遵循「告诉用途、软入口、硬出口」原则；`entries` 新增 `boot_mode: 'none' \| 'index' \| 'full'`（界面中文：`按需召回 / 目录常驻 / 全文常驻`），保持 `is_pinned = (boot_mode !== 'none')` 100% 向后兼容；`index` 固定只占 ~80 字摘要索引行、永不抢占全文预算，承接长篇参考手册 | 实测 `index` 索引行在主流客户端中唤醒 `kioku_get` 的触发率仍偏低 |
| 5 | 启动加载预算与场景分桶 | 默认全文展开预算由 `16,000` 字收紧至 **`6,000–8,000` 字**（默认取 `7,000` 字）+ 独立 `3,000` 字目录槽，并为 `agy` 等主流客户端补齐宿主上限。修复 `compileBoot` 排序反转：**精准场景优先于篇幅**（桶 1：匹配 `projects`/`runtimes` → 桶 2：匹配 `envs`/`realms` → 桶 3：无场景全局，且全局桶设 50% 占比帽）；单条 `full` 超 `2,400` 字自动降级为目录行 | 模型上下文遵循率大幅提升且用户普遍需要单次注入超过 15k 字全文 |
| 6 | 客户端自定义与场域聚焦解耦 | 放开词条 `runtimes` 接受任意合法 `SceneSlug`（不再受 11 项枚举限制），请求侧 `session.start` / `GET /v1/boot` / `kioku_boot` 向后兼容支持可选 `runtime?`/`env?`/`realm?`。`api_keys` 新增可空 `focus_realms` 仅作启动聚焦，**不改变 `allowed_realms` 的安全与检索硬边界** | `kioku-plugins` 统一改为所有终端强制独占密钥且不再共用全权密钥 |
| 7 | 四阶段漏斗跨记忆整理 | 保持 12 表架构、不引入图数据库。采用「零 LLM 候选图（pgvector HNSW 近邻聚类 + 同项目/主题 + 既有 1 跳邻居 + 场域隔离）→ 按任务拆分的 Micro-Task（2–4 条小簇全文去重/冲突、轻量补双链、近期 `episode` 反向对账老词条、常驻层防漂移与降级建议）→ 收件箱人工审阅 + 乐观锁落库」。严守合并克制原则：只合并真正重复/高度重叠词条，互补主题页优先 `link_entries` 建双链而非硬揉成大汇总页 | 词条规模突破数万条且需要多跳图谱推理引擎 |
| 8 | 主动单条与选中范围整理 | 编辑页阅读态新增「整理」下拉菜单，提供两档：**规范此条**（独立 HTTP/SSE 请求、不占全局 `dream` 锁、抽屉直出 Diff 预览 + 乐观锁应用 + 暂存待处理逃生阀）与**查找重复与关联**（单条锚点查近邻，产建议入收件箱并在抽屉内联审阅）。短期不向 MCP 开放整理工具，避免 Agent 套娃调用后台模型 | 未来出现需要 Agent 显式编排后台整理工作流的场景 |

长期有效的架构取舍在阶段 4 同步更新至 [docs/design.md](../design.md)（如涉及对 [ADR-0004](../adr/0004-flat-single-owner-v2.md) 的增量说明则补写 ADR）。
