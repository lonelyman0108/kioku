## 需要你手动做的事

### U01　配置 Docker Hub 的 secrets

- **在哪**：GitHub 仓库 Settings › Secrets and variables › Actions
- **操作**：新建 `DOCKERHUB_USERNAME`（lonelyman0108）与 `DOCKERHUB_TOKEN`（Docker Hub 的访问令牌，权限 Read & Write）
- **验证**：镜像发布的 workflow 登录 Docker Hub 一步通过
- **回滚**：删掉这两个 secrets
- **告诉 agent**：「Docker Hub 的 secrets 配好了」

### U02　审阅并合并镜像发布的 PR

- **在哪**：镜像发布的 PR（改了 workflow，只开不合）
- **操作**：审阅后合并
- **告诉 agent**：「镜像发布的 PR 合了」

### U03　打 v0.1.0

- **在哪**：本地仓库
- **操作**：合并发布 PR（`🔖 release: v0.1.0`，CHANGELOG 定稿）后 `git tag v0.1.0 && git push origin v0.1.0`
- **验证**：Release 页出现，GHCR 与 Docker Hub 能拉到 `0.1.0` 与 `latest`，系统信息页显示 v0.1.0 与提交
- **告诉 agent**：「v0.1.0 打了」

### U04　镜像包设为公开

- **在哪**：GitHub 个人主页 › Packages › kioku、kioku-postgres › Package settings
- **操作**：第一次推送后把可见性改成 Public（GHCR 新包默认私有）
- **验证**：未登录时 `docker pull ghcr.io/lonelyman0108/kioku:0.1.0` 成功

## 分阶段任务

### 阶段 1 · 系统信息

- [x] 构建时写入版本、提交、构建时间（本地取 git，镜像取构建参数），去掉 `KIOKU_VERSION` 配置项
- [x] 系统信息接口（只给实例管理员）：构建、运行环境、数据库、配置与后台任务
- [x] 「设置 › 实例 › 系统信息」小节与「复制诊断信息」
- [x] 账号菜单底部的版本号
- [x] 检查新版本的开关（默认关闭，每天最多一次），系统信息与概览的系统提醒
- [x] 测试与文档

阶段 1 的接口与约定（给阶段 2、3）：

- 镜像构建参数 `KIOKU_VERSION`、`KIOKU_COMMIT`（完整 sha）、`KIOKU_BUILD_TIME`（ISO 时间）在 Dockerfile 的构建阶段声明，打包时写进产物；都没传时版本是 `dev`。最后一段不再设 `ENV KIOKU_VERSION`，运行时设它也不生效。
- 系统信息接口 `GET /v1/instance/system`，检查新版本的开关 `PUT /v1/instance/update-check`，都只给实例管理员，不进 Python SDK。
- 系统信息从 `Deps` 取配置（`cookieSecure`、`trustedProxies`、`webDir`、`masterKey`、`jobs`），库名与主机从连接池的设置取，没有动 `config.ts` 与 `index.ts`。
