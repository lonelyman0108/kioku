## 决策摘要

1. **三层解耦**：
   - **服务商（Provider）**：`id`、`name`、`format`、`baseUrl`、`apiKey`（信封加密 + `sameOrigin` 沿用）。
   - **模型条目（Model Profile）**：挂载在服务商下，按 `kind` 分为 `chat` 与 `embedding`。
     - `chat` 携带 `id`、`label`、`model`、`thinking`（`default` | `off` | `minimal` | `low` | `medium` | `high`）、`thinkingStyle`（仅 `openai-chat` 可选：`auto` | `reasoning_effort` | `enable_thinking` | `none`）、`maxTokens`（可选；仅 `anthropic` 未填时自动补默认值）。
     - `embedding` 仅携带 `id`、`label`、`model`（不带对话专用参数）。
   - **用途绑定（Feature Bindings）**：
     - `extraction`：有序 `chat` 模型条目 ID 列表（Fallback 链）。
     - `dream`：`mode: 'inherit' | 'custom'`，默认沿用 `extraction`，可单独绑定 `chat` 模型链。
     - `privacy`：`off` | `http`（本地 NER `/detect`，保留独立地址与密钥）| `model`（从 `chat` 模型条目选 Fallback 链 + `minScore`）。
     - `embedding`：保留 `active` / `next` 双模型切换机制，各自保留逻辑模型标识 `model` + 有序 `embedding` 模型条目 ID 列表（1～5 个），保持 1024 维（`EMBEDDING_DIMENSIONS`）与余弦相似度 ≥ 0.99 测试校验。
     - `benchAgent`：在测试台从已配置 `chat` 模型条目下拉选择（默认优先用抽取主模型），单次请求不静默跨服务商 Fallback，确保知情同意（`consent`）地址与模型名准确。
2. **支持的 5 种 API 格式**（自研薄 `fetch` 适配器，复用 `withoutKey` / `fetchFailure` / `upstreamJson`）：
   - `openai-chat`：`/chat/completions`、`/embeddings`（支持 `dimensions`）。
   - `openai-responses`：`/responses`（对话专用）。
   - `anthropic`：`/v1/messages`（`x-api-key` + `anthropic-version`，`system` 顶层字段，必填 `max_tokens`，`thinking` 预算与 `signature` 透传；禁止挂载 `embedding`）。
   - `gemini`：`/v1beta/models/{model}:generateContent`（对话）与 `:batchEmbedContents` / `:embedContent`（`outputDimensionality: 1024`），`x-goog-api-key` 头（不拼 query），`thinkingConfig` 与 `thoughtSignature` 透传。
   - `ollama`：`/api/chat` 与 `/api/embed`（支持 `think` 与 `dimensions: 1024`）。
3. **思考强度默认策略**：`thinking === 'default'` 时不发送任何思考控制字段，确保普通/中转模型零侵入兼容。
4. **Fallback 触发边界**：仅在网络异常、单次超时、HTTP 错误或响应结构损坏/缺失内容时切换下一候选模型；调用方 `AbortSignal` 取消或业务输出 JSON 解析失败时不重试。区分单次超时与总时限；`extraction_runs.model` / `dream_runs.model` 写入实际命中的模型名；全部失败时聚合各节点经各自 `apiKey` 脱敏后的错误。
5. **存储、锁序、备份与迁移兼容**：
   - 存在 `settings` 表的 `model-providers` 与 `model-bindings`（及保留兼容视图），天然跟随全实例备份与恢复。
   - `SealedJson` 增加可选 `aad?: string` 字段，使旧格式（`settings:embedding`、`settings:extraction`、`settings:privacy_model`）在无主密钥的迁移阶段或从旧备份恢复后仍能正确解密；`crypto/rotation.ts` 同时覆盖 `model-providers`、`model-bindings.privacy.http.apiKey` 及遗留旧键；服务启动（`prepareMasterKey` 前）幂等迁移旧配置。
   - 全局固定加锁顺序：**先 `model-providers`（`FOR SHARE`/`FOR UPDATE`）再 `model-bindings`**，禁止反向加锁防死锁；删除正在被任一用途引用的服务商或模型条目时拦截报错；变更影响嵌入模型时刷新 `EmbedderSource` 缓存并让 `switchJob` 比对展开后的渠道指纹。
6. **测试台与界面合规**：
   - `BenchAgentMessage` 保留标准化字段（`role`/`content`/`tool_calls`/`reasoning_content`）并增加可选 `reasoning_blocks` 透传各家不透明签名，出站仅在 `block.format === target.format` 时还原；归一化各协议 `finishReason`。
   - 设置页保留 `models` 小节，严守 `copyRules.test.ts`（不出现禁用词如「层」，新组件登记 `UPSTREAM_KEYS`）与 `settingsPages.test.ts`（无圆角卡片/徽章、实心按钮与错误按钮约束）。
