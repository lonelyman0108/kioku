## 需要你手动做的事

编号 `U01…` 只在本计划里用，代码和注释不引用。

### U01　每期完成后部署

- **在哪**：Kioku 所在的 Docker 主机。
- **操作**：先按 README 备份，再拉取代码、重新构建镜像并启动；迁移在启动时自动执行。
- **验证**：`/v1/health` 返回 ok。构建镜像时把 `KIOKU_VERSION` 设成当前提交号（`git rev-parse --short HEAD`）的，返回的 version 应与它一致；没设时是 `dev`，这项就只能看管理界面。管理界面能打开，新页面可用。
- **回滚**：按 README「回滚」恢复备份（当前库改名留着，不要用 `--clean`）。
- **告诉 agent**：「第 N 期部署好了」。

### U02　建凭据源（第 2 期部署之后）

- **在哪**：管理界面「凭据 → 凭据源」。
- **操作**：为你在用的密码管理器新建凭据源，类型选对应的一项（Bitwarden 兼容的自建服务端也选 Bitwarden）。使用说明里写清 agent 在哪台机器上、用什么工具取值；不写主密码、会话令牌这类东西本身。
- **验证**：凭据源列表里能看到它。
- **回滚**：删掉这个凭据源（还没有凭据绑定它时可以删）。
- **告诉 agent**：「凭据源建好了」。

### U03　凭据迁移（agent 执行，你确认结果）

- **前提**：阶段 1 计划的 U03 切换已完成，签发的 Key 最高敏感级是 secret（agent 要读到现在标成 secret 的凭据节点）；U02 已完成；迁移前按 README 备份数据库。secret 的历史不含正文，迁移出错只能用备份恢复。
- **操作**：agent 读导入时标成 secret 的凭据节点，逐条处理：按你的凭据清单在密码管理器里找到对应条目，建一条绑定到它的凭据；密码管理器里没有的，改成 Kioku 托管。然后拼好替换后的正文（只有占位符，没有值）给你过目；你确认后，替换与降级（secret → private）在同一次更新里完成，不能先降级再替换：降级之后正文会进历史、全文检索和向量。降级后的正文还像有明文凭据时，服务端会拒绝这次更新。agent 只建凭据、改记忆，不往密码管理器里写。
- **验证**：凭据页里每条凭据都有记忆引用；agent 能按占位符取到值；这条记忆能被召回；全空间的明文凭据提醒为零。
- **回滚**：用迁移前的备份恢复。
- **告诉 agent**：「可以迁移凭据了」；迁移完由你核对结果。
- **之后**：Lore 的库里仍有这条凭据的明文，归档 Lore 之前要处理掉；记忆里「凭据要同步到几处」的规则，改成值只放在密码管理器、记忆里只放占位符。

## 分阶段任务

### 1 · 记忆体验

后端：

- [x] 记忆列表接口：按 domain、层、敏感级、来源、人格、应用、更新时间筛选和排序，游标分页，只返回成员读得到的
- [x] 历史接口：一条记忆的事件时间线（前后快照，secret 不含正文）；已删除记忆的列表；恢复到某一版、恢复已删除的记忆。查看与恢复的规则按设计 10 节「记忆」：「管理读取」是 `canRead` 与 `readableConditions` 加一个不看有效期与删除状态的选项，按显式读取算，`readableConditions` 能指定列，同一套条件用在记忆表与事件快照上，一致性测试两边都覆盖；记忆现在读不到就 404，前后快照有一边看不到的事件不显示，也不能拿来恢复；恢复到某一版只改正文、disclosure、priority 与关键词，只用同一归属、敏感级不高于现在的版本，快照没有正文时正文不变；恢复已删除的记忆是撤销软删除，并重新排队生成向量；都带版本号，照常走写入检查与 URI 冲突检查
- [x] 改层（通过 Key 不能在共享与个人的层之间转换）：`update` 支持 base、owner、private 互改；`move` 支持移入、移出 `persona://` 与 `app://` 并同时改层；新旧两边都要有写权限
- [x] domain 默认层：空间 owner 配置，管理界面新建时带出；Key 写入不变
- [x] 管理界面的搜索：复用召回（成员权限，不含 secret），再加上 URI 子串与关键词前缀的直接命中
- [x] 概览统计与活动流：各层 × 敏感级条数、最近修改、各应用 Key 最近一次使用、缺 disclosure 的记忆；活动的可见性与历史相同，凭据的事件不进活动
- [x] 向量状态：覆盖率与待处理数，手动重建（实例设置看全实例，概览看本空间）

前端：

- [x] 新布局：侧栏（⌘K、暗色模式、账号菜单）、窄屏可用、组件文案用中文；新用到的图标登记进 `icons.ts`（面包屑随记忆详情一起做）
- [x] 记忆树标出层、敏感级与 priority；列表视图与筛选
- [x] 记忆详情：阅读状态（marked + DOMPurify 渲染，关键词高亮并能跳到对应记忆）与编辑状态（原文、并排预览），属性栏；保留现有的未保存修改保护与版本冲突提示
- [x] 移动、改层、删除的对话框；历史时间线、对比与恢复；已删除记忆的恢复入口
- [x] 概览页、活动页；空间设置页（domain 默认层），新建记忆时按它带出层
- [x] 实例设置：向量状态与重建
- [x] 验证：新接口的集成测试（别的成员的私人层不出现在列表、历史、活动、搜索里，私人层改成共享层之后，之前的版本与那次改层在历史与活动里都看不到，对比也不用它们；记忆现在读不到时历史返回 404，拿旧快照的 id 恢复也被拒；过期、失效与删掉的记忆照样能看历史和恢复；新建与导入事件照常显示；恢复不改 URI、层、主人、敏感级与有效期，并发修改时返回 409；从改成 secret 时被抹掉正文的旧快照恢复，正文不变；恢复已删除的 secret 记忆，正文还在；editor 不能恢复现在是 secret 的记忆，空间 owner 能看 secret 记忆的历史；拿看不到的事件 id 恢复返回 404；撤销删除后向量重新生成；管理读取与 `canRead` 的一致性测试覆盖快照判断；secret 正文不出现在历史里；改层的权限与 URI 冲突）；无头 Chrome 走查（CSP 下没有 eval、没有外部请求，暗色模式，窄屏）

### 3 · 应用视角

- [ ] 人格继承覆盖：boot、召回与近期列表在读得到的节点之间按相对路径覆盖；Key 写人格层只限当前人格。覆盖不是权限，`canRead` 与 `readableConditions` 不变
- [ ] 人格：改名称、说明与继承（不能成环）；删除（有应用在用、被别的人格继承、或还有人格层记忆时不能删，已删除、还能恢复的记忆也算，否则数据库会把它们连带硬删除）；详情接口列出自己的、继承来的、被覆盖的节点和用它的应用
- [ ] 应用：详情页、改名、转给别的成员（空间 owner；沿用现有行为，转移时吊销它的全部 Key）；删除（还有应用层记忆时不能删，已删除、还能恢复的也算；Key 一起作废）
- [ ] Key：列表返回当前有效上限；界面显示签发上限与当前有效上限、权限矩阵（可切换会话上下文）；admin 显示为「跨人格 / 应用写入」
- [ ] 启动预览与召回调试台：按应用和它的某把 Key 模拟，只给应用主人；调试台列出管理界面看得到、这把 Key 却被过滤掉的记忆
- [ ] 召回事件：生命周期、MCP 搜索与 REST 召回时记录，不挡住响应；提示语最多存 200 字，存之前把像凭据的片段打码，应用配置里可以关掉；每条记下事件发生时的应用主人，明细只给他看
- [ ] 召回事件保留：明细默认 30 天（实例设置里可调），由清理任务删除，删除前并入每条记忆的累计统计
- [ ] 召回分析页：常被召回与从没被召回的记忆、各应用的调用量；记忆详情显示最近被召回的次数；概览的维护提醒加上「从没被召回」
- [ ] 验证：覆盖规则的集成测试（子人格的节点读不到时用祖先的）；Key 写祖先人格被拒；预览与调试对不是应用主人的成员返回 403；召回明细只有事件发生时的应用主人看得到，应用转移后新主人看不到之前的

### 4 · 多账号（以后再做）

- [ ] 账号：实例管理员创建、停用账号；本人改密码（其他会话与设备 Cookie 失效）、改显示名
- [ ] 成员：空间 owner 添加成员、改角色、移除（他的应用先转给别人或删除，转移时 Key 照样全部吊销；他的画像层、私人层记忆与凭据怎么处理要先定：空间 owner 看不到它们，留着就没人能管）
- [ ] 凭据：editor 能不能管理自己的托管凭据；要不要共享凭据
- [ ] 导入：owner 层与私人层的导入去重键加上导入者账号（阶段 1 留下的）
- [ ] 删除账号：他的画像层、私人层记忆会被数据库连带删除，但记忆事件留着快照里的正文，要一并清掉
- [ ] 验证：两个账号的画像层、私人层与凭据互不可见；成员被移出后 Key 作废
