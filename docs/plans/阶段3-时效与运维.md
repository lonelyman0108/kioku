| 4 | 向量固定 1024 维：换的模型要能按 `dimensions` 输出 1024 维，连通性测试时检查 | 维护者（2026-10-29）；主流模型都支持，换维度要迁移列与索引 | 要用只能输出别的维度的模型时 |

| 6 | 主密钥轮换：新旧两把同时配置（`KIOKU_MASTER_KEY` 与 `KIOKU_MASTER_KEY_PREVIOUS`），包装后的数据密钥旁记下主密钥的标识，后台任务按标识找出旧的、重新包装；正文的密文不动 | 记下标识，进度看得出来，中途停了也知道哪些还没换；只换数据密钥的包装，不用重新加密正文 | — |

## 需要你手动做的事

编号 `U01…` 只在本计划里用，代码和注释不引用。

### U01　每期完成后部署

- **在哪**：Kioku 所在的 Docker 主机。
- **操作**：先按 README 备份，再拉取代码、重新构建镜像并启动；迁移在启动时自动执行。
- **验证**：`/v1/health` 的 version 与部署的提交一致，管理界面能打开。
- **回滚**：按 README「回滚」恢复备份。
- **告诉 agent**：「第 N 期部署好了」，或让 agent 部署（每次都要你同意）。

### U02　轮换主密钥（第 2 期部署之后，可选）

- **在哪**：Kioku 所在主机的 `.env`。agent 不读也不改密钥文件，这一步只能你做。
- **操作**：生成新密钥；把现在的值移到 `KIOKU_MASTER_KEY_PREVIOUS`，新的填进 `KIOKU_MASTER_KEY`，重启。实例设置里显示轮换完成后，删掉 `KIOKU_MASTER_KEY_PREVIOUS` 再重启。新密钥存进 Vaultwarden。
- **验证**：实例设置里旧密钥的记录数降到 0；secret 记忆、托管的凭据、嵌入与抽取照常可用。
- **回滚**：轮换完成之前，把两项改回原来的值重启。
- **告诉 agent**：「主密钥换好了」。

### U03　备份用的存储桶（第 3 期部署之后）

- **在哪**：你的 S3 兼容存储，以及 Kioku 的「实例设置 → 备份」。
- **操作**：建一个只给 Kioku 用的存储桶和只能读写这个桶的访问密钥，在实例设置里填接口、存储桶与访问密钥，设好每天几点备份、保留几份。
- **验证**：「立即备份」成功，桶里出现备份文件。
- **回滚**：清空备份设置，定时备份随即停止。
- **告诉 agent**：「备份配好了」。

### U04　把带 `/bind` 的插件装到 AstrBot（第 7 期之后）

- **在哪**：AstrBot 所在的主机。
- **操作**：按插件的 README 更新 `plugins/astrbot_plugin_kioku` 并重载插件。也可以让 agent 来装（算部署，要你同意）。
- **验证**：私聊里发 `/bind` 能拿到一次性码。
- **回滚**：在 AstrBot 里换回旧版插件。
- **告诉 agent**：「插件更新好了」。

## 分阶段任务

### 1 · 嵌入多渠道与换模型

- [x] 设置：嵌入改成「模型标识 + 渠道列表」，每个渠道有接口地址、Key（加密存库）与请求用的模型名，按顺序回退，出什么错都换下一个（OpenAI 兼容的网关常把「这个渠道没有这个模型」报成 400）；召回算查询向量有 30 秒的总时限，几个渠道依次超时也不会等上几倍。现有的单接口设置读出来就是一个渠道，模型标识沿用现在的模型名，下次保存时换成新格式，不重嵌入（决策 5）
- [x] 连通性测试：逐个渠道请求同一段文本，维度不是 1024 的报错（决策 4）；和第一个通了的渠道的余弦相似度低于 0.99 时提示「可能不是同一个模型」
- [x] 换模型：管理界面里填新的模型标识与渠道（照抄现在的渠道时同一主机沿用已保存的 Key），后台按批补齐新模型的向量，召回一直用旧模型，期间新写入的两个模型都生成；看得到进度（已完成与总数、最近的错误），补齐后自动切过去、删掉旧模型的向量；补了一遍一条都没补上（被锁着跳过、已经排了重试的不算）或者出错时记下原因，隔十分钟再试，管理员也可以重试或不等补齐直接切换；中途可以放弃（正在跑的补齐会停下，删掉新模型已生成的向量）；服务启动时接着补
- [x] 验证：集成测试覆盖回退、维度检查、换模型期间召回用旧模型、补齐后切换、放弃、补不上时现在切换；走查设置页；README 写清换模型的步骤（见验证记录）

### 2 · 主密钥轮换

- [x] 包装后的数据密钥旁记下主密钥的标识（主密钥哈希的前 16 位，推不出密钥本身）：secret 记忆与托管的凭据加一列 `key_id`（0021 迁移），设置里的 API Key 记在 JSON 里。已有的记录在启动时补上标识（当前的与旧的挨个试，解得开才补）
- [x] 配了 `KIOKU_MASTER_KEY_PREVIOUS` 时，解密按标识选密钥，后台任务按空间找出旧标识的记录重新包装（每批一个短事务，被锁着的跳过、过一分钟再来），已删除、已过期的也换，设置里的 API Key 一起；实例设置里看得到主密钥的标识与还剩多少条，换完提示去掉旧密钥（决策 6）
- [x] 启动检查：库里有记录的标识两把都对不上时拒绝启动，并说明是哪类数据（主密钥配错了，带病启动只会让这些数据都读不出来）；库里有加密的数据却没配主密钥时也拒绝启动
- [x] 验证：集成测试覆盖轮换全过程（补标识、拒绝启动、轮换期间新写下的用新密钥、换完之后只配新的也都解得开）、被锁着的行之后再换、已删除的也换、只配新密钥时拒绝启动；README 与 `.env.example` 写清主密钥管哪些数据与轮换步骤（U02）。轮换是幂等的，中途重启之后接着按标识找剩下的

### 3 · 备份与迁移

- [ ] 备份格式：实例级的表（账号、实例设置、空间与成员等）与每个空间的内容（用 `withSpace` 读）逐表写成 JSON Lines，压缩后用主密钥派生的密钥加密（决策 2、7）；带格式版本、迁移数与主密钥标识。不含会话、登录计数、任务队列与对话缓冲
- [ ] 备份到 S3 兼容存储：实例设置里配接口、存储桶与访问密钥（加密存库）、每天几点备份、保留几份；「立即备份」；列出已有的备份；失败时在实例设置与概览里提示
- [ ] 恢复：一条命令（从 S3 或本地文件）恢复到空实例：先执行迁移，校验格式版本、迁移数与主密钥，再按原 id 写回，之后补齐向量；已初始化的实例拒绝恢复。恢复后要重新登录
- [ ] 按空间导出与导入：owner 导出一个空间（不含 Key、会话与召回事件），导入到另一个实例的新空间。目标实例的主密钥不同，secret 与托管的凭据值怎么带过去（例如导出时用口令重新加密）到这一项时再定
- [ ] 验证：集成测试覆盖备份后恢复的数据一致（含 secret、托管凭据、历史，向量重新补齐）、拒绝恢复到已初始化的实例、格式版本或主密钥不对时拒绝；本机用 MinIO 走一遍备份与恢复

### 4 · 保留期

- [ ] 实例设置里的保留期（天）：已删除的记忆连同它的历史、被推翻的事实、过期的会话摘要、抽取记录、凭据事件、已删除的凭据与凭据源。默认值在这一项开始时定，先按「和恢复的窗口相当」估
- [ ] 清理任务按保留期硬删除（向量、关键词、引用与召回统计跟着删），每类删了多少记下来，实例设置里看得到；还被用着的不删（例如还有有效绑定的凭据源）。删账号时快照里留下的明文（管理界面与凭据计划的待办）一起处理
- [ ] 验证：集成测试覆盖每一类到期删除、没到期的留着、还被用着的留着

### 5 · 有效期

- [ ] 策展记忆能设「有效到」（接口、MCP 工具与管理界面）：到期后不再召回、不进 boot，历史里看得到
- [ ] 让过期或被推翻的记忆重新生效（设计 10 节留到阶段 3 的那条）：清掉有效期或推翻标记，按管理读取读得到、也写得了才行；URI 已被别的记录占用时返回 409
- [ ] 验证：集成测试覆盖设有效期、到期后不召回、重新生效、URI 冲突

### 6 · Dream（只提建议）

- [ ] 待审队列加「建议」：合并（几条变一条，给出合并后的正文）、提炼（几条抽取的事实变一个策展节点的草稿）、过时（这条可能已经不对了，附理由）、审核（不可信的内容建议确认或删除，附理由）。成员确认后按建议执行，来源记为主人；拒绝的记下来，同样的建议不再提（决策 3）
- [ ] Dream 任务：按空间与人格每天跑一次，也能手动触发；只看上次以来新增或改动的内容；用抽取模型，用量计入同一份月度预算，用完就不跑；每次运行记一条记录
- [ ] 安全：建议的正文照常过明文凭据与占位符检查；Dream 读不到 `secret`；不可信的内容提炼出来的建议，确认之前不会出现在召回与 boot 里
- [ ] 验证：集成测试（假的模型）覆盖四种建议、确认后执行、拒绝后不再提、预算用完不跑、读不到 `secret`

### 7 · 验证码自助绑定

- [ ] 接口：私聊里用 Key 申请一次性码（8 位，10 分钟，只能用一次），在另一个平台的私聊里带上码，把这个平台账号的对象合并进发码的对象，规则同合并对象（同种类、标记的限制）；群里不发码，输错次数有上限。绑进已标记成员的对象要不要另外确认，到这一项时再定
- [ ] 插件：`/bind` 与 `/bind <码>` 两个命令；SDK 重新生成
- [ ] 验证：集成测试覆盖发码、绑定、过期、用过、群里不发、标记的限制、输错上限；插件用构造的事件测
