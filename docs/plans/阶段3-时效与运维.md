## 需要你手动做的事

编号 `U01…` 只在本计划里用，代码和注释不引用。

### U01　每期完成后部署

- **在哪**：Kioku 所在的 Docker 主机。
- **操作**：先按 README 备份，再拉取代码、重新构建镜像并启动；迁移在启动时自动执行。
- **验证**：`/v1/health` 的 version 与部署的提交一致，管理界面能打开。
- **回滚**：按 README「回滚」恢复备份。
- **告诉 agent**：「第 N 期部署好了」，或让 agent 部署（每次都要你同意）。

### U02　轮换主密钥（第 2 期部署之后，可选）

- **在哪**：Kioku 所在主机的 `.env`。agent 不读也不改密钥文件，这一步只能你做。
- **操作**：生成新密钥；把现在的值移到 `KIOKU_MASTER_KEY_PREVIOUS`，新的填进 `KIOKU_MASTER_KEY`，重启。实例设置里显示轮换完成后，删掉 `KIOKU_MASTER_KEY_PREVIOUS` 再重启。新密钥存进 Vaultwarden。
- **验证**：实例设置里旧密钥的记录数降到 0；secret 记忆、托管的凭据、嵌入与抽取照常可用。
- **回滚**：轮换完成之前，把两项改回原来的值重启。
- **告诉 agent**：「主密钥换好了」。

### U03　备份用的存储桶（第 3 期部署之后）

- **在哪**：你的 S3 兼容存储，以及 Kioku 的「实例设置 → 备份」。
- **操作**：建一个只给 Kioku 用的存储桶和只能读写这个桶的访问密钥，在实例设置里填接口、存储桶与访问密钥，设好每天几点备份、保留几份。
- **验证**：「立即备份」成功，桶里出现备份文件。
- **回滚**：清空备份设置，定时备份随即停止。
- **告诉 agent**：「备份配好了」。

### U04　把带 `/bind` 的插件装到 AstrBot（第 7 期之后）

- **在哪**：AstrBot 所在的主机。
- **操作**：按插件的 README 更新 `plugins/astrbot_plugin_kioku` 并重载插件。也可以让 agent 来装（算部署，要你同意）。
- **验证**：私聊里发 `/bind` 能拿到一次性码。
- **回滚**：在 AstrBot 里换回旧版插件。
- **告诉 agent**：「插件更新好了」。

## 分阶段任务

### 1 · 嵌入多渠道与换模型

- [x] 设置：嵌入改成「模型标识 + 渠道列表」，每个渠道有接口地址、Key（加密存库）与请求用的模型名，按顺序回退，出什么错都换下一个（OpenAI 兼容的网关常把「这个渠道没有这个模型」报成 400）；召回算查询向量有 30 秒的总时限，几个渠道依次超时也不会等上几倍。现有的单接口设置读出来就是一个渠道，模型标识沿用现在的模型名，下次保存时换成新格式，不重嵌入（决策 5）
- [x] 连通性测试：逐个渠道请求同一段文本，维度不是 1024 的报错（决策 4）；和第一个通了的渠道的余弦相似度低于 0.99 时提示「可能不是同一个模型」
- [x] 换模型：管理界面里填新的模型标识与渠道（照抄现在的渠道时同一主机沿用已保存的 Key），后台按批补齐新模型的向量，召回一直用旧模型，期间新写入的两个模型都生成；看得到进度（已完成与总数、最近的错误），补齐后自动切过去、删掉旧模型的向量；补了一遍一条都没补上（被锁着跳过、已经排了重试的不算）或者出错时记下原因，隔十分钟再试，管理员也可以重试或不等补齐直接切换；中途可以放弃（正在跑的补齐会停下，删掉新模型已生成的向量）；服务启动时接着补
- [x] 验证：集成测试覆盖回退、维度检查、换模型期间召回用旧模型、补齐后切换、放弃、补不上时现在切换；走查设置页；README 写清换模型的步骤（见验证记录）

### 2 · 主密钥轮换

- [x] 包装后的数据密钥旁记下主密钥的标识（主密钥哈希的前 16 位，推不出密钥本身）：secret 记忆与托管的凭据加一列 `key_id`（0021 迁移），设置里的 API Key 记在 JSON 里。已有的记录在启动时补上标识（当前的与旧的挨个试，解得开才补）
- [x] 配了 `KIOKU_MASTER_KEY_PREVIOUS` 时，解密按标识选密钥，后台任务按空间找出旧标识的记录重新包装（每批一个短事务，被锁着的跳过、过一分钟再来），已删除、已过期的也换，设置里的 API Key 一起；实例设置里看得到主密钥的标识与还剩多少条，换完提示去掉旧密钥（决策 6）
- [x] 启动检查：库里有记录的标识两把都对不上时拒绝启动，并说明是哪类数据（主密钥配错了，带病启动只会让这些数据都读不出来）；库里有加密的数据却没配主密钥时也拒绝启动
- [x] 验证：集成测试覆盖轮换全过程（补标识、拒绝启动、轮换期间新写下的用新密钥、换完之后只配新的也都解得开）、被锁着的行之后再换、已删除的也换、只配新密钥时拒绝启动；README 与 `.env.example` 写清主密钥管哪些数据与轮换步骤（U02）。轮换是幂等的，中途重启之后接着按标识找剩下的

### 3 · 备份与迁移

- [x] 备份格式：实例级的表（账号、实例设置、空间与成员等）与每个空间的内容（在一个可重复读的只读事务里逐个空间读）逐表写成 JSON Lines，压缩后用主密钥派生的密钥加密（决策 2、7）；带格式版本、迁移位置（最后一个的哈希与时间戳）与主密钥标识。不含会话、登录计数、任务队列、对话缓冲与向量。命令行 `backup.mjs` 先核对主密钥，边读边加密写到文件或标准输出
- [x] 备份到 S3 兼容存储（服务端，接口 `/v1/settings/backup`）：实例设置里配接口、区域、存储桶、前缀目录与访问密钥（Secret 用主密钥加密存库，主密钥轮换也换它）、每天几点（UTC）备份、留几份；每小时检查一次，到了钟点、那之后还没做成就做；「立即备份」、测试连通、列出已有的备份；做成之后按名字删掉超出份数的旧备份，别的文件不动；结果与错误记在设置里；恢复命令能直接从存储桶取最新的一份
- [x] 管理界面：实例设置里的备份卡片（填设置、测试连通、立即备份、列出备份、最近的结果与错误），没配备份、没做成或好几天没有新的一份时在概览里提醒实例管理员
- [x] 恢复：一条命令（`restore.mjs`，从备份文件或标准输入）恢复到空实例：校验格式版本、迁移与主密钥，新建的空库先迁移到做备份时的位置，再在一个事务里按原 id 写回、执行这个版本新增的迁移（较早的备份能用新版本恢复，失败时数据一条也不留下），服务启动后补齐向量；已初始化的实例拒绝恢复。恢复后要重新登录
- [x] 按空间导出与导入：owner 导出一个空间（不含 Key、会话与召回事件），导入到另一个实例的新空间。`secret` 与托管的凭据值用导出人设的口令加密带走，导入时换成目标实例的主密钥（决策 9）；只导出导出人读得到的，导入后归导入人（决策 10）。实例管理员导入，先检查文件再确认；目标实例没配主密钥时拒绝；迁移 0023 让导入自己刚建的空间时不加 URI 咨询锁（规则见设计 8 节）
- [x] 验证：集成测试覆盖备份后恢复的数据一致（含 secret、托管凭据、历史，向量重新补齐）、拒绝恢复到已初始化的实例、格式版本或主密钥不对时拒绝；本机用 S3 兼容存储走一遍备份与恢复（MinIO 已不公开发镜像，换成 versitygw）

### 4 · 保留期

- [x] 实例设置里的保留期（天）：已删除的记忆连同它的历史、被推翻的事实、过期的会话摘要、抽取记录、凭据事件、已删除的凭据与凭据源。默认 30 天（决策 11），1–3650 天，只给实例管理员看和改（接口 `/v1/settings/retention`）
- [x] 清理任务按保留期硬删除（向量、关键词、引用与召回统计跟着删），每类删了多少记下来，实例设置里看得到；还被用着的不删（例如还有有效绑定的凭据源）。删账号时快照里留下的明文（管理界面与凭据计划的待办）一起处理。条件写在 `retentionRules` 一处（见设计 8 节）；跟在每小时的清理后面每天（UTC）一次，逐个空间分批、锁着的跳过；硬删除记忆时导入事件留作去重记录；从备份恢复之后、保留期第一次生效时暂停一个保留期
- [x] 验证：集成测试覆盖每一类到期删除、没到期的留着、还被用着的留着（见验证记录）

### 5 · 有效期

- [x] 策展记忆能设「有效到」（接口、MCP 工具与管理界面）：到期后不再召回、不进 boot，历史里看得到。要比现在晚至少一分钟，修改时 null 清掉、原样带回不检查（规则见设计 4.4 节）
- [x] 让过期或被推翻的记忆重新生效（设计 10 节留到阶段 3 的那条）：清掉有效期或推翻标记，按管理读取读得到、也写得了才行；URI 已被别的记录占用时返回 409。「已过期」列表（含过期后被让出 URI 的，一并撤销删除）与对象页的「被推翻的事实」；删掉之后才过期的在已删除里撤销、回到过期状态；只收策展记忆；迁移 0022 让 URI 互斥触发器在有效期变化时也检查
- [x] 验证：集成测试覆盖设有效期、到期后不召回、重新生效、URI 冲突（见验证记录）

### 6 · Dream（只提建议）
