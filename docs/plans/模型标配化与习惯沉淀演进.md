# 双模型标配化、主题治理与习惯沉淀演进计划（Kioku）

> 状态：进行中　　开始：2026-11-27　　负责人：维护者 / agent
> 全部完成后，文件头改为「已完成 YYYY-MM-DD」，用 `git mv` 移到 `docs/archive/plans/`。

面向 Kioku 单人自托管 12 张扁平表架构（[ADR-0004](../adr/0004-flat-single-owner-v2.md)），承接 [常驻分层与整理演进.md](./常驻分层与整理演进.md)。在**对话模型（`chat_llm`）与嵌入模型（`embedding`）已成为 Kioku 核心标配**的前提下，对全仓开展「去无模型旧拐杖 + 安全/检索修漏 + 入口分拣拆解与跨会话习惯拾遗」两阶段演进，并严格按单一职责拆分为独立小 PR 推进：

1. **阶段 1（去拐杖 + 确定性修漏 + 全字段内省收敛，拆为 PR 2 / PR 3 / PR 4，零 DDL）**：
   - 修复受限访问密钥写入漏传 `realms` 写穿全局、`synthesizeFocus` 越界覆盖、Boot 混排无优先级声明、未嵌入新词条在混合检索中被 0.35 折重罚、`session.start` 兜底召回缺互斥过滤以及 `extractWikiLinks` 误抓代码块内示例等确定性缺陷。
   - 彻底治理主题标签（`topics`）膨胀与污染：不写洗词正则，改用「`loreParse` 停灌历史关键词 + `topics` 移出向量文本（长文补 `##` 小节纲要）+ 删 `sharedTopics >= 2` 启发式 + `tidy` 顺手按高频词表收敛至 1–5 个」四招反脆弱治本；同步删减靠硬编码中文词表猜语义的旧正则与写路径全表查询，解除批量 `tidy` 错位门控，删除随手记强塞无关全局常驻槽，并对齐首次启用对话模型联动默认开启增量整理。
   - 修复 `distill_episode` 无法显式清空单项目/环境锁死的问题，复用既有 `proposed_boot_mode` 列支持向 `/inbox` 建议常驻，`crossMemory` 合并护栏守住互斥 `envs` / `projects`。
2. **阶段 2（入口三槽分拣拆解 + 跨会话习惯拾遗与事实对账，拆为 PR 5 / PR 6，零新表）**：
   - 吸收 Mem0 / LangMem 的「入口结构化分拣」与 Letta / Claude Code AutoDream 的「睡眠巩固」精华，同时坚决守住「常青 Markdown 文档 + `/inbox` 人工审批」底线（不做过度原子化三元组、不囤积长周期全量操作流水、不绕过人工审批自动改库）。
   - `extractEpisodeBatch` 保持单次 fast 模型调用，升级为三槽结构化输出（`summary` 情节 + `facts` 事实要点 + `directives` 用户流程偏好/纠偏），按 `sessionId` 分段、`realms` 优先取 `focusRealms ∩ allowedRealms`。
   - 仅对带非空 `directives` / `facts` 信号的活跃 `episode` 做定向向量化（与业务正文解耦，日常 `recall` 严守 `kind = 'entry'` 不受污染）。
   - 在 `cross_memory` 漏斗中新增同场域跨 14 天重复偏好聚簇（≥ 2–3 次触发，向量匹配已有习惯词条，带出处证据与驳回防复发）与事实向量对账，由用户在 `/inbox` 一眼拍板。

**架构红线**：
- 严守 **12 张扁平表、无 RLS、自由 Markdown**（零新表、阶段 1 零 DDL、不引入 `entry_chunks` / `entry_variants` / 独立偏好表 / 图数据库）。
- **热路径零 Chat LLM 阻塞铁律**：`session.start` / `prompt.submit` / `turn.end` / `GET /v1/boot` / `POST /v1/recall` 及全部 MCP 工具永不同步调 Chat LLM，保留 2 秒向量超时回退 BM25 与故障兜底韧性。
- **权限与安全底线**：`access/scope.ts` 严格保持 JS 与 SQL 同步；受限密钥绝不允许写穿全局；`canFlowRealmInto` 绝不放宽 `realms`；全部后台整理 100% 经 `/inbox` 人工确认 + 乐观锁落库。
- **界面与协议兼容**：严格保持与 `kioku-plugins` 向后兼容；前端改动严守纸墨风、零圆角/零阴影与 `copyRules.test.ts` 用语规范。

## 决策摘要

| # | 决策 | 采纳 | 可推翻条件 |
|---|---|---|---|
| 1 | 主题标签（`topics`）治理策略 | 不写洗词正则；将 `topics` 从“关键词检索堆”收敛为 1–5 个粗粒度归类标签：`loreParse` 停灌 `glossary_keywords`、`topics` 移出 `buildEmbeddingText`、删 `crossMemory` `sharedTopics >= 2` 启发式，存量清洗交由已在调大模型的 `tidy` 附高频主题词表收敛 | 未来业务需要受控分类学词表（Taxonomy）而非自由标签 |
| 2 | 脆弱正则与批量 `tidy` 门控 | 删除靠硬编码中文动词/客户端名猜语义的正则（`TITLE_LOG_PAREN_RE`、`OBSOLETE_TITLE_RE`、`pinned_scope_hint` 及其写路径全表查询）；批量 `tidy` 改按版本水位与客观特征驱动，交由模型自判 `needed`；保留零误报客观红线与完整性校验 | 需要完全离线无 LLM 模式下的独立文本质量审查器 |
| 3 | 受限访问密钥写入边界 | 对配置了非空 `allowed_realms` 的受限密钥，`create` 缺省 `realms` 自动继承有效焦点场域（`focusRealms ∩ allowedRealms`，无则 `allowedRealms`），并禁止将词条写入或清空为全局 `realms = []` | 明确需要为受限终端增加独立的“允许写全局”细粒度开关 |
| 4 | 混合检索冷启动折损修复 | 区分词条“无当前模型向量行”与“有向量行但未进语义 TopK”：库里尚无向量行的新词条按纯全文得分参与排序，避免刚写入未嵌入完成时被 0.35 折过滤 | 改为同步阻塞生成向量后再返回写入成功 |
| 5 | 入口三槽分拣与常青存储平衡 | 吸收「入口拆解」但拒绝「存储层全量原子化」：`extractEpisodeBatch` 单次调用输出 `summary`（情节）、`facts`（事实要点）、`directives`（用户指令/偏好），仍存为单条 14 天 TTL `episode`；长期沉淀终点始终是常青 Markdown 词条 + `/inbox` 人审 | 出现面向结构化三元组推理的跨人知识图谱需求 |
| 6 | 跨会话偏好拾遗克制门槛 | 仅对非空信号做定向向量化（与业务正文解耦，绝不进入日常 `recall`）；`cross_memory` 仅在同 `realm` 下跨 ≥ 2–3 次不同会话/日期聚簇命中时产出带出处证据的 `/inbox` 建议，驳回后按稳定簇指纹不再复发 | 用户明确要求单次口头指令即强制生成待处理卡 |
| 7 | 本轮范围边界 | 本计划聚焦阶段 1 + 阶段 2，暂不纳入跨机 `git remote` 自动场域映射（涉及 `kioku-plugins` 双仓协议扩展，后续按实际需求另立计划） | 维护者提出多机混跑同密钥自动路由需求 |

- **验证**：单次偶发要求不骚扰 `/inbox`，跨多次会话的同类要求能被聚拢并正确匹配已有习惯词条。
