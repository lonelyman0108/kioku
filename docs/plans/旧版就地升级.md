# 旧版就地升级与插件迁移引导

记忆圈重构之后迁移重来了一份基线，旧库（v0.5.0 及更早）直接换镜像会拒绝启动、只在日志里留一句话；插件拿着旧访问密钥只看到 401。这份计划让直接升级的用户在管理界面里一键就地迁移，插件与命令行认得出「服务端换代」并引导重新接入。

## 决定

- 就地迁移：同一个库、同一把主密钥，不要求新建库、改连接地址。旧对象整体移进 `kioku_legacy` schema 保留，`public` 里建新基线，再从旧 schema 迁入；整件事在一个事务里，失败什么都不变。
- 旧访问密钥不迁移，只保留前缀与哈希（`legacy_api_keys`）用来识别：带旧密钥的请求回 401 加 `legacy_key`，提示重新接入。
- 界面一键迁移：用旧实例的管理员账号密码确认身份，先预览（整套迁移跑完再回滚）再执行。
- 暂不发版，先测试。

- [x] 运行状态 `legacy`：库里只有「重构之前的结构」这一个问题时不退出，只挂初始化应用，`/v1/health` 回 503 带 `legacy_database`，日志打印迁移指引
- [x] 就地迁移核心（`importer/legacyInPlace.ts`）：同一事务里读旧数据 → 移走旧对象 → 执行迁移 → 规划与写入 → 记下旧访问密钥；预览模式最后回滚
