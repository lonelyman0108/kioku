## 决策摘要

| # | 决策 | 采纳 | 可推翻条件 |
|---|---|---|---|
| 1 | TypeScript 固定 6.0 | typescript-eslint 8 不支持 7 | typescript-eslint 发布支持 7 的版本 |
| 2 | workspace 包导出 TS 源码，后端用 tsdown 打包 | 省掉每个包单独构建 | 需要把 contracts 发布到 npm 时改为构建产物 |
| 3 | 自建 PG 镜像：pgvector 官方镜像 + 编译 zhparser | 设计要求中文全文检索 | 换成应用侧分词时可改用官方 pgvector 镜像 |
| 4 | 身份表不开 RLS，内容表 FORCE RLS + 复合外键 | 鉴权前需要跨空间查 Key；外键检查不受 RLS 约束 | — |
| 5 | 拒绝以超级用户或 BYPASSRLS 角色运行 | 这两种角色会绕过 RLS | — |

总体设计见 `docs/design.md`。

## 分阶段任务

### 1.1 · 工程骨架

- [x] pnpm workspace：`apps/server`、`apps/web`、`packages/contracts`，根目录统一 typecheck / lint / format:check / test / build
- [x] 后端 Hono + zod-openapi，`/v1/health`、`/v1/openapi.json`，tsdown 打包
- [x] 管理界面 Vue 3 + Nuxt UI 4 + TanStack Query，开发时代理 `/v1`
- [x] CI 安装 Node 与 pnpm，跑完整门禁

### 1.2 · 数据层

- [x] `docker-compose.dev.yml`：PG16 + pgvector + zhparser
- [x] Drizzle schema：accounts、spaces、space_members、personas、apps、api_keys、subjects、memories（层、敏感级、来源作用域、provenance、有效期）、memory_paths、memory_events
- [x] 迁移脚本与启动时自动迁移
- [x] RLS：每个连接设置 `app.space_id`，所有带 `space_id` 的表强制按它过滤
- [x] 集成测试：CI 里起 PG 服务容器跑迁移和 RLS 用例

### 1.3 · 身份与授权

- [ ] API Key：生成、哈希存储、前缀显示、吊销
- [ ] 权限模型：Key 上限 ∩ 会话上下文 ∩ 配置，纯函数实现并单测
- [ ] 鉴权中间件：解析 Key → 设置空间与权限上下文
- [ ] 管理界面登录（账号密码 + 会话 Cookie）
- [ ] `secret` 应用层信封加密（`KIOKU_MASTER_KEY`）
