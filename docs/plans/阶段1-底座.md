## 决策摘要

| # | 决策 | 采纳 | 可推翻条件 |
|---|---|---|---|
| 1 | TypeScript 固定 6.0 | typescript-eslint 8 不支持 7 | typescript-eslint 发布支持 7 的版本 |
| 2 | workspace 包导出 TS 源码，后端用 tsdown 打包 | 省掉每个包单独构建 | 需要把 contracts 发布到 npm 时改为构建产物 |
| 3 | 自建 PG 镜像：pgvector 官方镜像 + 编译 zhparser | 设计要求中文全文检索 | 换成应用侧分词时可改用官方 pgvector 镜像 |
| 4 | 身份表不开 RLS，内容表 FORCE RLS + 复合外键 | 鉴权前需要跨空间查 Key；外键检查不受 RLS 约束 | — |
| 5 | 拒绝以超级用户或 BYPASSRLS 角色运行 | 这两种角色会绕过 RLS | — |
| 6 | 同源检查只针对带会话 Cookie 的写请求，用 Sec-Fetch-Site / Origin 与 Host | Hono 自带 csrf 会误拦没有 Content-Type 的 Bearer 请求 | — |
| 8 | 读不到与不存在统一返回 404 | 不泄露隐藏记忆的存在 | — |
| 9 | MCP 用无状态 Streamable HTTP | 不在进程里保存会话，方便多实例 | 需要服务端推送时改有状态 |
| 10 | 引用人格的外键在接口里校验同空间 | SET NULL 的复合外键会把 space_id 一起置空，drizzle 也不支持列级 SET NULL | 换到支持的迁移方式后改为数据库约束 |
| 11 | 向量 1024 维，嵌入配置存库、Key 加密 | HNSW 索引上限 2000 维；全实例一个模型才可比较 | — |
| 12 | boot 只收受信来源的策展层 | boot 被宿主当指令级上下文，不可信写入不能进入 | — |
| 13 | 每个 PR 先做代码审查再合并 | 用户要求（2026-10-26） | — |
| 14 | 一轮审查没有高危问题即合并，低危记入待办 | 用户确认（2026-10-26）；审查总能找出细节，需要明确的收敛标准 | — |
| 15 | 树浏览由可读后代推出，不强制父节点存在 | 父子可见性受多种因素影响，强制约束反复出现漏洞 | — |
| 16 | 登录失败计数存数据库，scrypt 加全局与按客户端的并发闸门 | 内存限流表无论如何淘汰都会被绕过或塞满 | — |
| 7 | 主人私聊的写入也按 untrusted 处理 | 平台账号证明身份的强度有限 | 有了 /bind 绑定后可按绑定状态放宽 |

总体设计见 `docs/design.md`。

## 分阶段任务

### 1.1 · 工程骨架

- [x] pnpm workspace：`apps/server`、`apps/web`、`packages/contracts`，根目录统一 typecheck / lint / format:check / test / build
- [x] 后端 Hono + zod-openapi，`/v1/health`、`/v1/openapi.json`，tsdown 打包
- [x] 管理界面 Vue 3 + Nuxt UI 4 + TanStack Query，开发时代理 `/v1`
- [x] CI 安装 Node 与 pnpm，跑完整门禁

### 1.2 · 数据层

- [x] `docker-compose.dev.yml`：PG16 + pgvector + zhparser
- [x] Drizzle schema：accounts、spaces、space_members、personas、apps、api_keys、subjects、memories（层、敏感级、来源作用域、provenance、有效期）、memory_paths、memory_events
- [x] 迁移脚本与启动时自动迁移
- [x] RLS：每个连接设置 `app.space_id`，所有带 `space_id` 的表强制按它过滤
- [x] 集成测试：CI 里起 PG 服务容器跑迁移和 RLS 用例

### 1.3 · 身份与授权

- [x] API Key：生成、哈希存储、前缀显示、吊销
- [x] 权限模型：Key 上限 ∩ 会话上下文 ∩ 配置，纯函数实现并单测
- [x] 鉴权中间件：解析 Key → 设置空间与权限上下文
- [x] 管理界面登录的后端（账号密码 + 会话 Cookie、失败限流、同源检查）；登录页在 1.6
- [x] 首次初始化：第一个账号与空间，咨询锁防并发
- [x] `secret` 应用层信封加密模块（`KIOKU_MASTER_KEY`）；接入写入路径在 1.4
