## 决策摘要

| # | 决策 | 采纳 | 可推翻条件 |
|---|---|---|---|
| 1 | TypeScript 固定 6.0 | typescript-eslint 8 不支持 7 | typescript-eslint 发布支持 7 的版本 |
| 2 | workspace 包导出 TS 源码，后端用 tsdown 打包 | 省掉每个包单独构建 | 需要把 contracts 发布到 npm 时改为构建产物 |

| 5 | 拒绝以超级用户或 BYPASSRLS 角色运行 | 这两种角色会绕过 RLS | — |
| 6 | 同源检查只针对带会话 Cookie 的写请求，用 Sec-Fetch-Site / Origin 与 Host | Hono 自带 csrf 会误拦没有 Content-Type 的 Bearer 请求 | — |
| 8 | 读不到与不存在统一返回 404 | 不泄露隐藏记忆的存在 | — |
| 9 | MCP 用无状态 Streamable HTTP | 不在进程里保存会话，方便多实例 | 需要服务端推送时改有状态 |
| 10 | 引用人格的外键在接口里校验同空间 | SET NULL 的复合外键会把 space_id 一起置空，drizzle 也不支持列级 SET NULL | 换到支持的迁移方式后改为数据库约束 |
| 11 | 向量 1024 维，嵌入配置存库、Key 加密 | HNSW 索引上限 2000 维；全实例一个模型才可比较 | — |
| 12 | boot 只收受信来源的策展层 | boot 被宿主当指令级上下文，不可信写入不能进入 | — |
| 13 | 每个 PR 先做代码审查再合并 | 用户要求（2026-10-26） | — |
| 14 | 一轮审查没有高危问题即合并，低危记入待办 | 用户确认（2026-10-26）；审查总能找出细节，需要明确的收敛标准 | — |
| 15 | 树浏览由可读后代推出，不强制父节点存在 | 父子可见性受多种因素影响，强制约束反复出现漏洞 | — |
| 16 | 登录失败计数存数据库，scrypt 加全局与按客户端的并发闸门 | 内存限流表无论如何淘汰都会被绕过或塞满 | — |
| 7 | 主人私聊的写入也按 untrusted 处理 | 平台账号证明身份的强度有限 | 有了 /bind 绑定后可按绑定状态放宽 |
| 17 | 管理界面的权限不超过成员能拿到的 Key：editor 最高到 private，应用层只能写自己是主人的应用 | 审查发现 editor 能在界面里改写别人应用的启动规则 | — |
| 18 | Lore 导入不迁历史版本，按导入事件里的 Lore 节点去重；只写导入者自己的应用；像凭据的节点只提醒，不自动标 secret | secret 不进召回和 boot，标不标要由人权衡；重复导入不能写回已删除的记忆 | — |
| 19 | 插件只转交上下文文本；会话开始的附加块（近期记忆、项目召回）不等嵌入接口、只收受信来源；Claude Code 的启动上下文控制在 9,500 字以内 | 记忆服务出问题不能挡住会话；钩子输出超过 1 万字时模型只看到预览 | — |
| 20 | 单容器部署：后端托管管理界面；备份用数据库超级用户；服务不发 HSTS | 应用角色受 RLS 约束导不出数据；HSTS 交给 HTTPS 代理决定 | 发布镜像到仓库时再定标签策略 |

## 需要你手动做的事

编号 `U01…` 只在本计划里用，代码和注释不引用。三步按顺序做，迁移期间 Lore 照常运行。

### U01　部署 Kioku

- **在哪**：跑 Lore 的那台 Docker 主机（或任何你想放 Kioku 的主机），在仓库根目录操作。
- **操作**：`cp .env.example .env`，按注释生成密码与 `KIOKU_MASTER_KEY` 并另外保存主密钥；经 HTTPS 反向代理访问时设 `KIOKU_TRUSTED_PROXIES=1`，代理就在本机时再设 `KIOKU_BIND=127.0.0.1`，只在局域网用 http 访问时设 `KIOKU_COOKIE_SECURE=false`；然后 `docker compose -f docker-compose.example.yml up -d --build`。打开管理界面完成初始化。
- **验证**：`curl <地址>/v1/health` 返回的 JSON 里 `status` 是 `ok`；能登录管理界面。
- **回滚**：`docker compose -f docker-compose.example.yml down`；要连数据一起删时再加 `-v`。
- **告诉 agent**：「Kioku 部署好了，地址是 …」。
- **结果**：2026-10-27 完成。部署在维护者家里的 Docker 主机上，镜像从源码构建，自带 PG16；`/v1/health` 正常，管理界面已初始化。

### U02　从 Lore 导入

- **在哪**：Kioku 的服务容器里（Lore 的数据库要能从容器访问，见 `docs/migrate-from-lore.md`）。
- **操作**：先不加 `--apply` 看导入计划；按导入计划里的「提醒」决定哪些节点标 secret（路径或正文像有凭据的节点会列出来），标了的不进召回和 boot，需要带 secret 级的 Key 显式读取；确认后加 `--apply`。
- **验证**：在「应用与 Key」里为 Claude Code 应用签发 Key（U03 接着用），用它请求 `/v1/boot`，得到 `core://agent`、`persona://default/soul`、`app://<应用>/agent`、`preferences://user`。
- **回滚**：导入前先按 README 备份；回滚就用备份恢复。
- **告诉 agent**：「导入完了，标了 secret 的是 …」。
- **结果**：2026-10-27 完成。全部节点导入；维护者只把 1 个纯凭据节点标为 secret，其余和 Lore 一样明文导入。各节点正文的哈希与 Lore 逐条一致；再执行一次全部跳过，并解开了已存的密文。用 Key 调 `/v1/boot` 的端到端检查并入 U03，由新会话的 `<kioku-boot>` 验证。

### U03　切换 Claude Code

- **在哪**：日常用 Claude Code 的机器。
- **操作**：用 U02 签发的 Key（要让 agent 读 secret 级记忆时，签发时最高敏感级选 secret）；`/plugin install kioku --marketplace lonelyman0108/kioku`，填服务地址与 Key；停用 Lore 的插件。
- **验证**：新会话开头出现 `<kioku-boot>`，提到项目名时出现 `<recall>` 候选；`/mcp` 里能看到 kioku 的 8 个工具。
- **回滚**：停用 kioku 插件，重新启用 Lore 插件。
- **告诉 agent**：「切到 Kioku 了」，之后由 agent 确认结束标志并归档本计划。
- **状态**：维护者选择先不切换（2026-10-27），两边并行。导入工具只补新增节点，并行期间在 Lore 里改过的节点不会同步过去；切换前先用导入前的备份恢复，再重新导入，让 Kioku 跟上 Lore。

## 待办（审查中发现的低危问题）

按收敛标准（一轮审查没有高危问题即可合并），以下低危问题留到后续 PR：

- [x] 树浏览每层截断 500 个时返回 `truncated` 标记（MCP 的列表同时提示）
- [x] `claimUri` 只保留释放过期记录，冲突检查只交给数据库触发器与唯一索引，去掉 TS 里重复的咨询锁与冲突条件
- [x] `children()` 去掉与 SQL 重复的排序；`findLive` 只取仍有效的记录，不再需要排序
- [x] 过期会话与登录失败计数改由定时任务清理，清理时跳过被锁的行，不会和登录计数的事务互相等待
- [x] `children()` 每级本身的记忆改成一个按 id 排序的聚合，各字段取自同一行
- [x] 嵌入任务写回时用 `SKIP LOCKED` 锁行，跳过的记忆稍后重新排队
- [x] 反向代理转发来的地址不是合法 IP（例如 nginx 的 `unknown`）时，归入「未知客户端」计数，而不是记到代理自己的地址上
