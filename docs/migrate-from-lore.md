# 从 Lore 迁移

有两种做法，规则相同：管理界面（上传 Lore 的导出文件，或者填 Lore 的地址，见「在管理界面导入」），和命令行工具（直接读 Lore 的数据库或导出文件，见「步骤」）。

导入只读访问 Lore，把节点分别写进目标记忆圈与导入者的个人圈，并为每条正式词条分配全实例唯一的不可变短 ID（`m-xxxxxx`）、保留原 Lore 路径至 `legacy_uris`（支持 `kioku_get` 按旧路径兼容检索）。可以重复执行：按 Lore 节点去重，导入过的不再写入，导入后在 Kioku 里删除或迁移了的也不会被写回；且不再因目标路径占用丢弃条目。迁移期间两边可以并行，各客户端确认后再逐个切过来。并行期间在 Lore 里改过的节点，加 `--sync` 执行就能带过来（见「同步」）。

## 映射规则

| Lore | Kioku |
|---|---|
| `core://agent` | 目标记忆圈通用正式词条（`topics: ['agent']`），同一记忆圈下的接入实例都会纳入加载 |
| `core://soul` | 目标记忆圈独立人格（`persona_traits` 中设定键 `soul`），默认人格标识 `default`，不存在且这次需要写入时新建 |
| `core://agent/<runtime>` | 目标记忆圈带 `runtime` 切面条件（`when.runtime`）的正式词条，同时关联或新建导入者的对应接入实例与 `runtime` 词表项 |
| `core://` 下的其他节点 | 目标记忆圈正式词条，中间段自动转为 `topics` 主题标签 |
| `preferences://<路径>` | 导入者个人圈正式词条，敏感级 `internal`，自动带入 `'preferences'` 等主题标签（开启「本人私聊提权」后本人私聊可用） |
| 其余的 `<分区>://<路径>` | 导入者个人圈正式词条，敏感级 `private`，`<分区>` 与中间段转为 `topics` 主题标签 |

标题取 Lore 正文的第一个 `#` 标题，没有就用坐标的最后一段；标成机密的只用最后一段，不从加密的正文里取。

- 优先级（`priority`）、触发场景（`disclosure`）、关键词（`glossary`）保留，创建时间沿用 Lore 的。关键词按接口规则过滤：单字的丢弃，每条最多 50 个（保留有效长度词条）。
- 新建的接入实例和原本没有默认人格的接入实例，默认人格设为导入的人格，与 Lore 里所有客户端共用 `core://soul` 一致。这次不写入新的 `core://soul` 时不建空人格；要新建的接入实例没有对应写入目标时不建。
- 历史版本不迁移：每条词条记一条 `import` 事件，带上 Lore 的节点 uuid、原路径和旧版本数。Lore 的库留作归档。召回事件也不迁移。
- Lore 的别名（同一节点的多条路径）只导入最早的一条，其余在计划里列出。

## 明文凭据

Lore 里常有直接写在正文里的密码与令牌。Kioku 里推荐把值放进凭据，正文只留占位符 `{{cred:<标识>#<字段>}}`：agent 用 `kioku run` 取值，值不进对话，取用留有访问记录。

1. 导入之前先在「凭据」页把值备好：已经在密码库里的，在「凭据 › 密码库」里给条目起标识；不在密码库里的，新建一条凭据（连接设了去处时写进去处的集合，没有时由 Kioku 托管）。
2. 用管理界面导入。疑似明文按值和导入人已有的凭据比对：托管的，以及已对应到条目字段的密码库凭据。对得上的那一处，计划里写「与凭据「名称」`标识#字段`同值」，默认勾着「写成占位符」，写入时换成占位符；写入时还会核对它仍等于这条凭据这个字段现在的值。比对时不可用的连接、读不到的托管凭据，计划里给出个数。
3. 这几种照原样写，计划或结果里写明原因：
   - 目标放不进占位符：占位符只能放在本人、敏感级不低于私密的记忆里，导入为通用（`core://`）或本人 · 内部（`preferences://`）的不换；
   - 值也出现在坐标、标题、触发场景或关键词里；
   - 值太短；
   - 写入时凭据的值已经变了。
4. 已导入的节点只同步、不换，同步后可以在记忆详情或待处理里转存为凭据。
5. 对不上的，导入为机密，或者照原样导入后到「待处理 › 疑似明文凭据」里逐条转存为凭据（和密码库的条目按值比对，对上了可以当场起标识；对不上的新建一条凭据），规则误判的标「不是凭据」。

命令行导入不换占位符，只在计划的「提醒」里列出这些节点。

## 在管理界面导入

在「设置 › 记忆圈 › 导入与导出」里操作，需要目标记忆圈所有者权限。

1. 选来源：
   - **上传导出文件**：在 Lore 的设置页导出（`GET /api/backup?action=export`），导出时不要带召回事件。文件在浏览器里先裁到导入要用的五张表，Lore 的 `app_settings`（里面有接口的 API Key）、事件与整理日记都不上传，废弃版本也不带正文。
   - **从地址拉取**：Lore 的地址与 API Token，由服务端去拉，需要实例管理员权限。API Token 不保存；地址里不能带账号密码、查询与片段。Lore 要从 Kioku 的服务能访问到。
2. 看计划：每个节点写到哪个记忆圈、属于正式词条还是独立人格设定、有哪些同步差异（不含正文）。标注会进入启动加载的节点、正文引用的凭据、疑似含明文凭据的节点；疑似明文和导入人个人圈已有凭据同值的，写明与哪条凭据的哪个字段相同（见「明文凭据」）。这些内容会按受信来源写入，所以只导入自己导出的文件。
3. 勾选：标记机密（已导入的节点不可勾选，要到记忆详情里改）、这次不导入（已导入的节点就是这次不同步），或者把和已有凭据同值的那一处写成占位符（默认勾着）。
4. 确认。执行时会重新读来源、重新算计划，和看过的不一致就要重看，勾选保留。文件比这个记忆圈已写入的数据旧时，同步会把正文改回去，所以要单独确认。

不要和命令行工具同时执行同一记忆圈导入：界面的上传并发门控挡不住命令行。

## 步骤

1. 在管理界面完成初始化，确认导入用的账号是目标记忆圈所有者。要导入机密记忆时，服务端必须配置了 `KIOKU_MASTER_KEY`。
2. 先看导入计划，不写入任何数据。加 `--circle <标识或 id>` 可指定目标共享记忆圈（账号只有一个共享圈或只有个人圈时可省略）：

   ```bash
   export DATABASE_URL=<Kioku 的连接串> LORE_DATABASE_URL=<Lore 的连接串> KIOKU_MASTER_KEY=<与服务相同>
   node apps/server/dist/ctl.mjs import-lore --account <用户名> --secret infra://office_network/credentials
   ```

   也可用 `--file <JSON 文件>` 从导出的 JSON 文件读取；用 Docker 部署时在服务容器里执行（从源码构建的在 `docker compose` 后面加 `-f docker-compose.build.yml`）：

   ```bash
   docker compose exec -e LORE_DATABASE_URL=<Lore 的连接串> \
     kioku kioku-ctl import-lore --account <用户名>
   ```

3. 检查计划里的「提醒」：正文、触发场景或关键词里疑似有密码、令牌的节点会列出来。命令行不会把值换成占位符，要换就用管理界面导入（见「明文凭据」）。也可以标为机密（`--secret <Lore 的 URI>`，可重复，对已导入的节点不生效）：正文加密存储，召回和启动加载都不再返回它。
4. 确认无误后加 `--apply` 执行。导入完成后会安排一次向量补齐，服务正在运行时由它的后台任务接手。
5. 在「接入实例」里为需要的接入实例签发透镜访问密钥（若需同步使用个人圈里的偏好与凭据，可关联个人圈作为客场圈）。

## 同步

导入过的节点在 Lore 里又改了，加 `--sync` 再执行一次（先不加 `--apply` 看计划）：

- 正文、标题、优先级、触发场景与关键词改成 Lore 里现在的，每条记一条「同步导入」事件。敏感级不跟着改：要改成机密或从机密改回来，在管理界面里改。
- 只更新导入（或上次同步）之后在 Kioku 里没人改过的词条：版本号还是导入工具最后写下的那个。改过或删除了的都不动，只在计划里列出来。
- Lore 里换了路径且映射到不同位置/归属的节点也会安全保留并列出，不会重复写入。
- Lore 里删掉的节点只列出来，Kioku 里保留。
- 计划之后、执行之前有人改了某条词条，执行时按版本号拒绝这一条，其余照常。
- 导入过机密词条时，同步需要设置与服务相同的 `KIOKU_MASTER_KEY`。
- 转存过凭据的词条：同步时先按个人圈凭据现在的值把 Lore 正文换回占位符再比较；读不到值或值已变化时跳过并给出指引。

## 对照检查

导入后在管理界面的「测试台」里选对应接入实例的透镜访问密钥（已关联个人圈），发一次 `session.start`（默认回滚，不留痕迹）：

- 启动加载输出里应当已编译包含原 `core://agent`、`persona://default/soul`（独立人格设定段）、对应 `runtime` 切面规则以及个人圈高优先级非限定偏好；「记忆」页里按 `core://...` 或新生成的短 ID `m-xxxxxx` 均可直接查到对应词条。
- 「收到的原文」里不应当出现大段重要规则因为超出字符预算被列进「未展开的启动词条」。

再用测试台发几句 `prompt.submit`，试试 `kioku_search`、`kioku_get`（也可以直接传旧 `core://...` 测试 `legacy_uris` 兜底），看召回与切面亲和分是否符合预期；没有配置嵌入模型时召回只走全文与关键词两路，在「设置 › 实例 › 模型」里配好嵌入接口后会补齐向量。
